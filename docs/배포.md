작업은 **전부 `main` 에 있고 원격(`origin/main`)에도 올라가 있다.** 머지할 것이 없다.

| | |
|---|---|
| main | `3c18675` — origin/main 과 같음 (2026-09-11) |
| 테스트 | **537개 전부 통과 · 건너뜀 0** · 타입 오류 0 · 프로덕션 빌드 통과 |
| 확인 명령 | `npm run check` (타입 + 빌드 + 테스트) |

> 옛 가지는 전부 정리됐다. 원격에 남은 브랜치는 `main` 하나다.
> Vercel 은 기본으로 `main` 을 배포하므로 **바로 2단계로 간다.**

### ✅ 배포 직전에 확인한 것 (2026-09-11)

**`data/seed.json` 이 서버리스 번들에 딸려가는가.** 이게 이 앱의 DB 인데
`src/lib/repo.ts:26` 이 **런타임에 파일로 읽는다** — 번들에 안 들어가면
Vercel 에서 **모든 화면이 500** 이다. 빌드 산출물로 직접 셌다:

```bash
grep -rl seed.json .next/server --include=*.nft.json | wc -l   # 18
find .next/server -name '*.nft.json' | wc -l                   # 26
```

**화면 18개 전부 들어 있다.** 빠진 8개는 `_not-found` · API 4개 ·
`pages/_app|_document|_error` 로 **애초에 시드를 안 읽는 것들**이다.
→ Next 의 자동 추적이 잡았으므로 `next.config.ts` 에 `outputFileTracingIncludes` 를
넣을 필요가 없다. **다만 시드를 읽는 방식을 바꾸면 이 확인을 다시 해야 한다.**

## 3. 주소를 환경변수에 넣고 한 번 더 배포

카카오톡으로 체크리스트 링크를 보내는 것이 이 제품의 실제 경로인데,
주소를 안 넣으면 **미리보기가 안 뜬다.**

1. Vercel 프로젝트 → **Settings → Environment Variables**
2. 추가:

| Key | Value |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | 방금 받은 주소 (예: `https://store-note-xxxx.vercel.app`) |
| `ANTHROPIC_API_KEY` | <https://console.anthropic.com> 에서 발급 (`sk-ant-…`) |
| **`STORE_PIN`** | **매장 번호. 넣어야 레시피가 실제로 막힌다** — 아래 ★ |

⚠️ **`ANTHROPIC_API_KEY` 에는 `NEXT_PUBLIC_` 을 붙이면 안 된다.** 붙이면 키가
브라우저 파일에 그대로 박혀서 누구나 꺼내 쓸 수 있다. 지금 코드는 서버에서만 읽는다.

> 키를 안 넣어도 나머지 화면은 전부 돈다. **촬영 목록 만들기만**
> "AI 키가 설정되지 않았습니다" 라고 뜬다.

### ★ `STORE_PIN` — 이걸 안 넣으면 레시피가 공개된다

레시피는 영업비밀이다. 그런데 화면의 번호 잠금은 **브라우저 안에서만** 돈다 —
서버는 잠금과 무관하게 레시피를 그려서 보내므로, 주소를 아는 사람이
[페이지 소스 보기] 를 하면 배합이 그대로 보인다.

`STORE_PIN` 을 넣으면 **서버가 쿠키를 확인하고, 없으면 레시피를 아예 안 그린다.**
보낼 것이 없으니 소스를 열어도 없다.

| 넣으면 | 안 넣으면 |
|---|---|
| 직원이 번호를 한 번 넣으면 12시간 열린다 | 레시피가 **누구에게나** 열린다 |
| 소스를 열어도 배합이 없다 | 소스에 배합이 그대로 있다 |
| — | 화면 위에 **빨간 띠**가 떠서 그 사실을 알린다 |

> **왜 안 넣으면 막지 않게 했나** (사장님 결정 2026-09-10)
> 환경변수를 깜빡한 채 심사 시연에 들어가면 레시피가 통째로 안 열린다.
> 그게 더 큰 사고다. 대신 **조용히 열지는 않는다** — 화면이 크게 말한다.

**6자리 이상**으로 잡을 것. 4자리는 후보가 10,000개뿐이다. 시도 제한이 있지만
서버 메모리에 세므로 서버가 여러 개면 각자 따로 센다 — 느리게 할 뿐 못 막는다.

⚠️ `NEXT_PUBLIC_` 을 붙이면 안 된다. 붙이면 브라우저 파일에 박혀서 무의미해진다.
⚠️ 번호를 바꾸면 직원들이 다시 넣어야 한다 (쓰던 쿠키가 무효가 된다).

### ★ Anthropic 콘솔에서 예산 한도를 걸 것 (이게 진짜 상한이다)

`/api/shoot-plan` 은 **이 앱에서 돈이 나가는 유일한 경로**다. 앱 안에도
횟수 제한을 걸어뒀지만(한 사람 20회/시간 · 전체 60회/시간), **서버 메모리에
세기 때문에** 서버가 여러 개로 늘어나면 그만큼 곱해지고 재시작하면 0 이 된다.

<https://console.anthropic.com> → **Billing → Usage limits** 에서 월 한도를
걸어둘 것. 앱 쪽 제한은 사고를 **늦추는** 장치이고, 금액을 **끊는** 것은 여기서만 된다.

> `STORE_PIN` 을 넣으면 AI 도 그 문 뒤로 들어간다 — 번호를 아는 사람만 쓴다.
> 안 넣으면 횟수 제한만 남는다.

3. **Deployments → 맨 위 → ⋯ → Redeploy**

> **빌드 시점에 박히는 값이라 재배포가 필요하다.** 나중에 주소를 바꿔도 마찬가지.

| **★ 레시피가 진짜 막혔나** | 아래 한 줄 | 배합이 **안 나와야** 한다 |

### ★ 레시피가 진짜 막혔는지 (이건 눈으로만 보면 모른다)

화면에 자물쇠가 떠도 **소스에는 배합이 들어 있을 수 있다.** 그게 이번에 고친
바로 그 문제다. 눈이 아니라 이걸로 확인한다 — 로그인하지 않은 상태에서:

```bash
curl -s https://내주소/r/shokupan | grep -c 강력분
```

| 나온 수 | 뜻 |
|---|---|
| **0** | ✅ 제대로 막혔다. 서버가 레시피를 안 보낸다 |
| 1 이상 | ⛔ **`STORE_PIN` 이 안 들어갔다.** 환경변수를 넣고 재배포할 것 |

브라우저에서 보려면 `주소/r` 을 열었을 때 **위에 빨간 띠**
("이 서버는 매장 번호가 설정되어 있지 않습니다")가 뜨는지 본다.
그 띠가 보이면 아직 안 막힌 것이다.

⚠️ **지표(`/api/log`)는 서버 파일(`data/events.jsonl`)에 쓴다.**
Vercel 은 파일 시스템이 배포마다 초기화되므로 **배포본에서는 지표가 안 쌓인다.**
지금은 깨지지 않고 조용히 버려지기만 한다 — Supabase 를 붙일 때 같이 옮긴다.

## 5. 배포하면 달라지는 것 — 알고 있어야 할 것

- **주소를 아는 사람은 누구나 연다.** 검색에는 안 걸리지만(noindex + robots) 링크는 열린다.
  체크리스트를 카톡으로 돌리는 것이 원래 설계이므로 이건 의도된 것이다.
- **레시피는 매장 번호로 가려지지만 그건 가림막이다.** 페이지 소스에 재료가 들어 있다.
  **실매장 레시피 수치를 넣기 전까지만 안전하다.**
- **데이터는 여전히 각 브라우저에만 있다.** 태블릿에서 넣은 출퇴근이 폰에서 안 보인다.
  기기가 바뀌면 `/backup` 으로 옮겨야 한다. 이게 Supabase 가 필요한 이유다.
