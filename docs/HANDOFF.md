## 2-b. 데이터 설계와 검사기 6종 (2026-09-11 신설) — **여기부터 읽을 것**

지금 앱은 `localStorage` 로 돌지만, **Supabase 로 갈 때 쓸 설계는 이미 다 됐고 검증도 끝났다.**
심사 피드백을 1차 5건 · 2차 2건 · 3차 3건 받았고 전부 반영돼 있다.

| 파일 | 무엇 |
|---|---|
| `db/schema_v2.sql` | **정본.** 표 37개 · 외래키 93 · 유니크 45 · 정책 38. 붙여 넣으면 그대로 돈다 |
| `db/schema_v2.dbml` | 같은 것의 그림. dbdiagram.io 에 붙이면 ERD 가 그려진다 (**경고 0건**) |
| `docs/이관_매핑.md` | 지금 `seed.json` + `localStorage` 의 칸을 어느 표로 옮기는지 |

### 검사기 6종 — `npm run check` 가 전부 돈다

```bash
npm run check     # 타입 + 빌드 + 테스트 543 + DB 검사 6종
```

| 스크립트 | 답하는 질문 | 건수 |
|---|---|---|
| `verify:db` | 막아야 할 걸 **실제로 넣으면** 거부되는가 | 55 |
| `audit:db` | 지적 한 줄마다 그걸 막는 제약이 있는가 + 그림↔SQL 일치 | 27 |
| `sweep:db` | 규칙마다 **적용돼야 할 자리가 전부 채워졌는가** | 11 |
| `dbml:db` | dbdiagram 이 경고할 관계가 있는가 | 2 |
| `docs:db` | **제출 문서의 숫자가 지금 값과 같은가** + 사실 아닌 문장이 남았는가 | 2 |
| `counts:db` | 현재 숫자를 `db` 폴더의 `.counts.json` 에 뽑는다 (git 에는 안 올린다. 위 검사들이 여기에 기록한다) | — |

**데이터베이스를 설치할 필요가 없다.** PGlite(PostgreSQL 18 을 WebAssembly 로 옮긴 것)를
쓰기 때문에 `node db/verify.js` 한 줄이면 누구나 재현한다.

### ★ 이 체계가 왜 생겼는지 — 안 지키면 같은 사고가 난다

2026-09-11 하루에 **같은 실수를 다섯 번** 했다. 전부 모양이 같다 —
**지적받은 자리만 고치고, 같은 규칙이 적용돼야 할 나머지를 안 봤다.**
`sweep.js` 가 그래서 있다. 규칙을 하나 정하면 **그 규칙이 적용될 자리를 전부 세어서** 빠진 곳을 찾는다.
실제로 아무도 지적하지 않은 구멍 3개를 스스로 찾아냈다.

지켜야 할 규율 세 가지:

1. **새 검사기를 만들면 반드시 일부러 고장 내서 정말 잡는지 확인한다.**
   "만들었다" 와 "작동한다" 는 다르다. 통과하는 검사기는 안 만든 것과 같다.
2. **0건은 통과가 아니다.** 훑을 대상이 0개면 실패로 처리한다
   (경로가 틀려서 아무것도 안 읽고 "이상 없음" 이 나오는 것이 가장 위험하다).
3. **문서에 숫자를 손으로 적지 않는다.** `db/docs.js` 가 제출 문서의 인용 12곳을
   현재 값과 대조한다. 어긋나면 `npm run check` 가 **실패한다.**
   심사가 *"상단에는 29건 통과라고 적혀 있는데 하단에는 실행한 적 없다고 적혀 있다"* 를
   지적한 뒤에 만든 장치다. 숫자를 적고 싶으면 `db/docs.js` 의 `주장` 목록에 같이 넣을 것.

## 4. 손대기 전에 알아야 할 함정

**전부 테스트로 못 박아뒀다. 지우거나 "고치지" 말 것.**

### 계산·데이터

- **g ↔ ml 환산 안 한다.** 밀도를 모른다(밀가루 0.55, 우유 1.03). 바꾸면 원가가 조용히 틀린다
- **단가 못 구한 재료를 0원으로 안 센다.** 원가율이 낮게 나오고 사장님이 그 숫자로 가격을 정한다
- **"추출량"에는 단가를 안 붙인다.** 붙이면 원두가 두 번 계산된다. `settings.excluded` 가 그것
- **자정 넘기는 마감조.** 23:00→01:00 을 그냥 빼면 −22시간이다. `shiftClock.isOnDuty()` 를 쓸 것
- **★ 매장의 하루는 새벽 4시에 바뀐다.** 하루 단위 화면은 `businessDay()`. 달력 날짜 금지
- **★ CSV 맨 앞 BOM 을 지우면 엑셀에서 한글이 전부 깨진다.** `Blob.text()` 는 BOM 을 떼므로 **검증은 바이트로**
- **★ CSV 칸이 `= + - @` 로 시작하면 앞에 `'` 를 붙인다.** 엑셀이 수식으로 실행한다
- **되돌리기는 합치지 않고 덮어쓴다.** 어느 쪽이 맞는지 앱이 모르는데 조용히 고르면 급여가 틀린다

### 도메인 — 함부로 약화시키지 말 것

- **★ 주기 숫자(`everyDays`)를 시드에 박지 않는다. 매장이 정한다.** 제빙기를 매일 닦는
  매장에 "1개월마다" 를 띄우면 그 화면은 처음부터 틀린 말을 한다. 시드는 전부 `null`
- **★ 주기 점검은 "그날 체크" 가 아니라 "마지막으로 한 날" 을 남긴다.** `sop:cycleDone` 은 **안 지운다**
- **★ `optionOf`(배치) 와 `optional`(셈) 은 다른 것이다.** 진행률 분모와 빨간 안내 분모가
  **다른 것은 일부러다** — 르방을 쓰는 매장에서 "다 했습니다" 가 거짓이 되면 안 된다
- **★ "안 하면 —" 은 리드타임이 없는 항목에만 띄운다.** `쿠팡으로 메울 수 있습니다` 처럼
  **안 해도 괜찮다고 알려주는 문장은 해롭다**
- **★ 매장에서 쓰는 말을 내가 지어내지 않는다.** `프렙` 을 `만들기` 로 바꿨다가 되돌렸다
- **주민등록번호 칸을 만들지 않았다.** 개인정보보호법 제24조의2. **요청이 와도 만들지 말 것**
- **PIN 은 두 겹이고 성격이 다르다.** 매장 PIN(레시피)은 `STORE_PIN` 을 넣으면 **서버가 막는다.**
  **사장님 PIN(돈·사람)은 여전히 가림막**이라 접근 통제로 소개하면 안 된다 (§6)

### 도구·환경

- `src/lib/` 안의 런타임 import 에는 **`.ts` 확장자를 붙여야 한다** (`node --test` 가 못 찾는다)
- **`next/server` 를 import 하는 파일은 `node --test` 로 못 돌린다.** 그래서 AI 응답 거르기가
  라우트가 아니라 `src/lib/shootPlan.ts` 에 있다
- **dev 서버를 켠 채 `npm run build` 하면 `.next` 가 덮어써져 dev 서버가 죽는다.** 타입만 볼 땐 `npm run typecheck`
- **워크플로·서브에이전트가 도는 중에 빌드하지 말 것.** 매번 다른 오류가 나서 코드 문제로 착각한다
- **Bash `node -e` / `python -c` 안의 백틱은 셸이 먹는다.** 스크립트 파일로 만들어 실행할 것
- `.claude/launch.json` 은 `node.exe` **절대경로**를 쓴다. **건드리지 말 것**
- **`presentation/*.html` 두 개의 `<script>` 는 바이트까지 같아야 한다** — `tests/singleFile.test.ts` 가 확인한다.
  Next 앱을 고치면 **단일 파일도 같이 고친다.** 단 **AI 기능은 넣지 않는다**(외부 요청 0건 규율)

## 5. 아직 안 풀린 것 (정직하게)

**기능은 계속 늘었는데 매장 투입은 여전히 0곳이다.**

문제 자체는 대표자의 16년 현업 경력으로 안다. 하지만 *이 제품이 그 문제를 푸는지*는
다른 질문이고, **B4(점주가 왜 돈을 내는가)는 하나도 안 풀렸다.**

원가율·인건비율·남은 돈을 화면에 올린 건 맞다. **그런데 그건 화면을 만든 것이지
지불 의사의 근거가 아니다.** 오히려 그럴듯한 숫자가 근거 없는 확신을 키운다.
→ [`01_MVP기획서.md` §3.4-B](deliverables/01_MVP기획서.md)

**★ B4 칸을 추측으로 채우지 말 것.** 증거가 0이라는 사실 자체가 지금의 정확한 상태다.

**기능 추가 요청이 오면 "매일 열리는 이유" 를 늘리는지 먼저 따진다.**
매일 열리는 것: 프렙 · 출퇴근(하루 2번) · 발주(아침) · 매출(마감).
드물게 열리는 것: 원가 · 거래처 · 계약서.

## 6. 잠금 세 겹 — 헷갈리면 제품이 망가진다

| | 아는 사람 | 가리는 것 | 막으려는 상대 |
|---|---|---|---|
| **사장님 PIN** (`ownerGate`) | 사장님만 | 매출·원가·거래처·계약서·근무표·인건비 | 같은 매장 **직원** |
| **매장 PIN** (`serverGate` ★서버) | **직원 전부** | **레시피**(`/r` 계열 4 · `/prep` 계열 2 · `/shoot`) | **매장 밖 사람** |
| 없음 | — | 체크리스트·교육 모드·발주 | — |

레시피에 사장님 PIN 을 걸면 **직원이 매일 여는 화면이 막혀 제품이 죽는다.**
⚠️ **"사장님 PIN 이 풀리면 레시피도 열린다" 는 이제 조건부다.** 그 배려는
`storeGate.isUnlocked()` 에 있고, 그 함수는 **브라우저 폴백에서만** 쓰인다 —
`STORE_PIN` 이 설정돼 있으면 서버는 쿠키만 보므로 사장님 PIN 을 풀어도 레시피는 안 열린다.
반대 방향은 예나 지금이나 아니다 (매장 PIN 으로 매출이 열리지 않는다).

### 한계 — 발표에서 어느 겹을 말하는지 밝힐 것

✅ **매장 PIN 은 2026-09-10 부터 서버가 막는다** (`ServerStoreGate` · `src/lib/serverGate.ts` · `fb1389a`).
쿠키가 없으면 레시피를 **아예 안 그린다.** 이 자리에는 *"서버 컴포넌트가 HTML 에 실어
보낸다"* 는 한계가 적혀 있었고, 확인 명령도 같이 있었다 — **이제 안 나오는 것**이 정상이다.

```bash
curl "$주소/r/shokupan" | grep 강력분     # 0건이어야 한다
```

⚠️ **단서 셋. 이걸 빼고 말하면 과장이 된다.**

1. **`STORE_PIN` 환경변수를 안 넣으면 막지 않는다** (사장님 결정 — 시연 중 레시피가
   통째로 안 열리는 쪽이 더 큰 사고라서). 대신 화면이 빨간 띠로 크게 알린다
2. **무차별 대입을 완전히는 못 막는다.** 시도 제한이 메모리에 있어 서버가 여러 개면
   각자 센다 → **PIN 은 6자리 이상**
3. ⛔ **사장님 PIN(돈·사람)은 여전히 가림막이다.** 검사가 브라우저 안에서 돌고
   시급·매출은 `localStorage` 에 그대로 있다. **여기를 "보안"이라고 부르면 거짓이 된다**

⚠️ **레시피 수치가 아직 플레이스홀더라 지금은 샐 영업비밀이 없다.
실매장 수치를 넣기 전에 `STORE_PIN` 을 먼저 넣을 것** → [배포.md](배포.md) §3.
