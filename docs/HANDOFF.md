## 확정된 결정 (그리고 이유)

여러 턴에 걸쳐 뒤집힌 것들이라 이유까지 남겨둠. **되묻지 말 것.**

**네이티브 앱 안 만든다.** 신입이 첫날 앱 설치할 확률보다 링크 누를 확률이 훨씬 높다. 모바일 웹 + 필요하면 나중에 PWA.

**타겟은 개인 매장. 프랜차이즈 아님.** 프랜차이즈는 본사가 사진 매뉴얼을 이미 만들어준다 — 해결된 문제다. 본사에 파는 길(배포 채널)도 있지만 영업 사이클이 길어서 지금은 아님.

**태블릿이 1순위 기기.** 매장에 태블릿은 이미 다 깔려 있다(사용자 확인). 개인폰은 주방에서 젖은 손·위생 규정 때문에 불리. 카톡 공유 링크는 보조 수단.

**경쟁자는 벽에 붙은 코팅 체크리스트다.** 그래서 *체크리스트를 준다*는 것 자체는 새 가치가 0이다. 새로 얹는 건 딱 셋: **사진·영상 / 수정 비용 0 / 기록**.

**영상이 본체, 글은 자막이다.** 주방 교육은 읽기가 아니라 시연·모방이다. 기준이 사람마다 다른 이유는 매뉴얼이 없어서가 아니라 각자 머릿속 시연이 달라서다. 그러니 만들 것은 "더 좋은 문서"가 아니라 **가장 잘하는 사람의 시연을 박제한 것**.

**촬영 모드가 편집 화면보다 먼저다.** 영상이 본체면 병목은 "사장님이 안 찍는다"로 옮겨간다. `<input type="file" accept="video/*" capture>`로 폰 기본 카메라를 열어서, 편집 없이 항목당 30초씩, 주방 한 바퀴 도는 동안 다 찍히게.

**첫 촬영은 신입한테 시킨다.** 선배가 시연하고 신입이 찍는다. 어차피 시연은 하니까 추가 비용 0이고, 신입은 더 집중하고, 다음 신입이 그걸 본다. 콜드스타트가 공짜로 풀린다.

**AI의 역할은 텍스트 초안이 아니라 촬영 목록 생성이다.** 포지션명 넣으면 "이 18개를 찍으세요"가 나오고 폰 들고 한 바퀴. AI와 촬영이 한 흐름.

**레시피가 있어야 한다.** 체크리스트만 있으면 신입 올 때만 열려서(월 1회) 사장님이 존재를 잊는다. 레시피는 매일 열린다. 메뉴 30개는 벽에 못 붙이므로 여기선 태블릿이 종이를 확실히 이긴다.

**레시피는 공개 링크로 두면 안 된다.** 영업비밀이다. 체크리스트는 링크가 새도 상관없지만 레시피가 새면 사고다. **체크리스트=공개 링크, 레시피=매장 PIN**으로 나눈다. "회원가입 없이"라는 원래 MVP 전제가 레시피 쪽에서는 깨진다.

**프렙 리스트가 가장 강한 데일리 훅이다.** 매일 아침 반드시 열리고, 숙련자도 쓰고, **수량이 매일 바뀌어서 종이로 못 한다.** 다른 기능은 다 종이로 어느 정도 된다.

**오더는 프렙의 상류다.** 프렙 수량이 정해지면 발주가 따라 나온다. 따로 만들 필요 없고 나중에 자동으로 붙는다.

**"시간표"는 직원 근무 스케줄이다** (업무 시간표 아님). 처음에 제외했던 "급여/스케줄 시스템 **연동**"과는 다른 것이므로 모순 아님. 그리고 부가 기능이 아니라 **어떤 화면을 먼저 띄울지 고르는 기준**이 된다.

**공용 태블릿이라 저장 방식이 화면마다 다르다.** 교육 모드가 localStorage에 진도를 남기면 앞사람 체크가 다음 신입에게 보인다. 그래서 교육 모드는 sessionStorage + `runId`(시작할 때마다 새로 발급, 끝나면 삭제). 체크리스트는 localStorage(날짜별 초기화). 검증 완료.

## 카페·베이커리라서 특별한 것

**리드타임이 이 업종의 핵심.** 오늘 하는 프렙의 절반은 내일을 위한 것이다.

| 항목 | 리드타임 | 안 하면 |
|---|---|---|
| 콜드브루 추출 시작 | 12~24h | 내일 콜드브루 판매 불가 |
| 반죽 제조 후 냉장 | 12~18h | 내일 아침 빵 없음 |
| 르방 갱신 | 매일 | 복구에 2~3일 |
| 냉동 생지 해동 | 12h | 내일 해당 품목 없음 |

**오늘은 아무 일도 안 일어나고 내일 아침에 터진다.** 신입이 스스로 알 방법이 없고, 어제 뭘 걸어놨는지 기억에 의존해서 종이로는 못 잡는다. **이게 제품이 종이를 이기는 가장 확실한 지점.**

**계량·배수가 필수.** 베이킹은 g 단위, "1배합=식빵 6개"인데 9개 필요하면 1.5배. 다른 업종이면 나중 기능인데 여기선 없으면 레시피가 반쪽.

**영상으로 박제할 1순위 4개** (기준이 가장 안 맞는 항목):
추출 테스트 합격 기준 / 스팀 밀크 온도·거품 / 베이커리 잔여 할인·폐기 전환 / 반죽 발효 완료 판단.

자세한 하루 흐름은 [docs/day-flow.md](docs/day-flow.md).

## 실행 / 환경 주의사항

```bash
npm run dev
```

- `http://localhost:3000` 사장님 화면 / `/t/grill-day1` 교육 모드 / `/p/grill-day1` 체크리스트
- **Node는 winget으로 새로 설치했다.** 셸에서 `node`가 안 잡히면 PATH를 새로고침해야 함:
  `$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")`
- 그래서 `.claude/launch.json`은 `node.exe` **절대경로**를 쓴다. 건드리지 말 것.
- **dev 서버를 켜둔 채 `npm run build` 하면 `.next`가 덮어써져서 dev 서버가 죽는다.** 빌드 전에 서버를 끌 것.
- 큰 파일은 Bash heredoc이 깨진다(따옴표 파싱 에러). Write 도구를 쓸 것.

```
src/app/t/[slug]/page.tsx   ← 교육 모드

public/photos/              ← 회색 플레이스홀더. 실제 사진으로 교체
```

## 쌓이는 지표

| event | 뜻 |
|---|---|
| `view` | 체크리스트 링크를 열었다 |
| `training_start` | 태블릿 교육 시작 |
| `critical_confirm` | 필수 항목 확인 눌렀다 |
| `training_complete` | 교육 완료 (`durationSec` = 실제 소요) |
| `survey` | "선배에게 몇 번 물어봤나" |

검증 대상 가설: *"신입이 체크리스트+영상만 봐도 선배가 붙어있는 시간이 줄어든다."*
`training_complete.durationSec` + `survey`를 붙여서 본다.

참고로 선배가 붙어있는 시간은 **가르치는 시간 + 지켜보는 시간**인데, 보통 뒤엣것이 더 길다.
그래서 "신입이 따라 한 걸 찍어 올리고 선배가 나중에 확인"하는 비동기 구조가 가설을 가장 직접적으로 공격한다. 아직 미구현.
