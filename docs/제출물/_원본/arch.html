정적/동적이 갈리는 것도 같은 이유다

ServerStoreGate 는 쿠키를 읽는다. 쿠키를 읽는 화면은 Next 가 미리 구워둘 수 없다 — 사람마다 다르니까. 그래서 그 7개만 동적이다.

반대로 OwnerGate 화면은 서버가 아무것도 모르는 빈 껍데기라 구워도 아무 일이 없다. 빠르고, 안전하고, 서버 비용이 0 이다.

이 구조가 깨지는 조건 — 알고 있어야 한다

지금 레시피 수치는 표준 비율 자리표시자다. 그래서 서버 게이트가 없어도 실제로 새는 영업비밀이 없다. 실매장 수치를 넣는 순간 사정이 달라진다.

그리고 STORE_PIN 환경변수를 안 넣으면 서버가 막지 않는다 — 대신 화면 위에 빨간 띠가 뜬다. 심사 시연 중에 레시피가 통째로 안 열리는 것이 더 큰 사고라고 판단해서 그렇게 했다. 의도된 선택이고, 조용히 열지는 않는다.

계산을 lib/ 으로 뺀 이유

화면(.tsx)은 브라우저가 있어야 돌아서 테스트하기 어렵다. 그래서 틀리면 돈이 걸리는 계산은 전부 lib/ 의 순수 함수로 뺐다 — 원가 · 인건비 · 리드타임 · 단위 환산 · 영업일. 그 결과 테스트 코드가 본 코드의 절반을 넘는다(7,184 : 13,927).

빌드된 HTML 을 검사하는 이유

화면이 아니라 결과물을 본다. 잠긴 레시피가 페이지 소스에 남는 사고는 화면을 봐서는 안 보인다. 그래서 .next 의 HTML 을 직접 긁어서 배합이 들어 있는지 센다. .next 가 없으면 건너뜀으로 크게 표시한다 — 조용히 통과하는 것이 제일 위험하다.
