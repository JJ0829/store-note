★ 시연 데이터 가명화(11.1)를 촬영보다 앞에 둔 이유

촬영 한 장이 빠지는 것보다 심사장 스크린에 직원 실명과 시급이 뜨는 쪽이 훨씬 큰 사고다. 그리고 시연 중에는 잠금이 풀려 있어서 사장님 화면의 가림막이 보호해 주지 않는다. 시간이 모자라면 11.1 을 먼저 하고 촬영을 줄인다.

배포(10)가 데이터 이관(10.6)보다 먼저인 이유 — 일부러 이 순서다

일반적인 흐름은 DB → 기능 → 검수 → 배포인데 이 프로젝트는 배포가 먼저다. 데이터가 서버가 아니라 각 기기의 브라우저에 있기 때문이다. 그래서 «이관 전에 배포하면 시연 중 입력한 데이터가 사라진다»는 일은 이 앱에서는 일어나지 않는다 — 서버 파일에 쓰던 것은 이용 기록 하나뿐이었고, 그건 9/12 에 서버 DB 로 옮겼다(10.0).

대신 배포본의 진짜 한계는 따로 있다 — 데이터가 태블릿마다 따로 쌓여서 교대 인계가 안 된다. 이건 숨기지 않고 발표에서 먼저 말한다(12.1 대본에 포함). 10.6 을 보완으로 둔 것은 남은 날이 닷새이고, 이관보다 잠금(10.4 · 10.5)이 먼저이기 때문이다.
