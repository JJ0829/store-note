## 4. 시큐어 코딩 기준

이 코드베이스에 실제로 존재하는 결함에서 역산한 규칙이다. 일반론은 쓰지 않았다.

### 4-1. `innerHTML`을 쓰는 단일 파일 버전 — `esc()` 필수 지점

**단일 파일 2개(`presentation/app.html`, `presentation/매장수첩.html`)에만 적용된다.** Next 앱(`src/`)은 `innerHTML` 0건이고 React가 자동 이스케이프하므로 이 절이 필요 없다.

**규칙 1 — 템플릿 리터럴이 `.innerHTML`로 들어가면, 보간되는 모든 값에 `esc()`를 씌운다. 예외 없음.**

```js
// ❌ 지금 코드 (매장수첩.html:923)
box.querySelector("#y").innerHTML =
  `${r.yield.amount}${r.yield.unit} → ...`;

// ✅
box.querySelector("#y").innerHTML =
  `${esc(r.yield.amount)}${esc(r.yield.unit)} → ...`;
```

**규칙 2 — "이 값은 숫자니까 안전하다"는 판단을 하지 않는다.** `yield.amount`는 지금 숫자지만 폼 입력이 문자열로 들어올 수 있고, 검사하는 코드가 없다. **타입 보장이 없는 값은 전부 `esc()`를 통과시킨다.**

**규칙 3 — "지금은 시드 상수라 안전한 곳"도 씌운다.** `app.html:786, 789`(프렙 화면 배수 계산기)는 현재 `recipeBy()`가 `DATA.recipes`만 조회해서 사용자 입력이 도달하지 못한다. **데이터 출처가 바뀌는 순간 동일 취약점이 된다.** 방어를 데이터 흐름에 의존시키지 않는다.

**규칙 4 — `el()` / `<template>`을 방어로 세지 않는다.** `<script>`는 안 돌지만 `img/onerror`처럼 문서 삽입 시 발동하는 핸들러는 그대로 실행된다(실측 확인). 상세 화면은 애초에 라이브 노드에 직접 대입이라 template이 개입조차 안 한다.

**규칙 5 — 새 코드는 `innerHTML` 대신 `textContent`.** 문자열 조립이 필요하면 구조는 `innerHTML`, 값은 `textContent`로 나눈다.

```js
// ✅ 권장 패턴
const li = document.createElement("li");
const span = document.createElement("span");
span.className = "amt";
span.textContent = `${fmt(i.amount, s)}${i.unit}`;  // 이스케이프 불필요
li.append(span);
```

**규칙 6 — 파일 3개는 수동 사본이다. 한 곳을 고치면 세 곳을 다 고친다.**
`presentation/README.md`가 "원본을 고치면 이 파일도 같이 고쳐야 한다. 자동으로 따라가지 않는다"고 명시한다. **V-05 조치로 관리 대상이 3개 → 2개로 줄었다.** 남은 두 파일은 `presentation/app.html`(알맹이)과 `매장수첩.html`(감싼 것)이고, 차이는 **정확히 313바이트**다 — `diff`로 그것만 나오는지 확인하는 습관을 들일 것.

### 4-2. 사용자 입력을 `style` / 속성에 넣지 않는다

**규칙 7 — `style="..."` 속성에 변수를 보간하지 않는다.**
단일 파일 `renderRoster()`의 `colorOf()`가 `style` 속성에 미이스케이프로 들어가지만 고정 배열 `SEC_COLORS` 값만 반환해 주입이 불가능하다. **이 안전은 우연이다.** 섹션 색을 사용자가 고르게 하는 순간 깨진다. CSS 값이 필요하면 클래스명으로 매핑한다.

```js
// ❌ 절대 금지
`<div style="color:${userValue}">`
// ✅
const SAFE = { 제빵: "sec-bake", 바: "sec-bar", 홀: "sec-hall" };
`<div class="${SAFE[s.section] ?? "sec-default"}">`
```

**규칙 8 — `href` / `src` 속성에 변수를 보간하지 않는다.** `javascript:` URL 주입 경로가 된다. 현재 `src/`는 모든 `href`가 리터럴 `/` 접두라 안전하다. **이 상태를 유지한다.**

**규칙 9 — `aria-label` 등 속성에 개인정보를 넣지 않는다.**
현재 `매장수첩.html:1103, 1176`이 직원 **이름**을 `aria-label`에 넣는다. `esc()`는 통과하므로 XSS는 아니지만, 속성값은 CSS 속성 선택자(`[aria-label^="김"]`) + `background:url()` 조합으로 한 글자씩 유출될 수 있는 유일한 표면이다. 이메일·전화번호는 텍스트 노드에만 있어(`:1174-1175`) 이 표면 밖이다 — **그 상태를 유지할 것.**

### 4-3. `mailto:` 조립 시 개행·특수문자

**규칙 10 — `mailto:` URL의 각 파라미터는 반드시 `encodeURIComponent()`.**
현재 정상이다: `RosterView.tsx:105-107`, `presentation/` 단일 파일 2개의 `sendMail`. `bcc`·`subject`·`body` 각각 개별 인코딩 → **헤더 인젝션과 파라미터 덧붙이기 불가.** 이 상태를 깨지 않는다.

```js
// ✅ 현재 코드 (유지)
const url = `mailto:?bcc=${encodeURIComponent(bcc)}` +
            `&subject=${encodeURIComponent(subject)}` +
            `&body=${encodeURIComponent(body)}`;
```

**규칙 11 — 본문에 개인정보를 넣지 않는다(V-03).** 인코딩은 주입을 막을 뿐 **과다 수집을 막지 못한다.** `mailto:`의 실제 위험은 인젝션이 아니라 페이로드 내용이다. 본문에 넣을 필드는 화이트리스트로 정한다: **섹션·이름·근무배정만.**

**규칙 12 — 문자열 연결로 URL을 만들 때 개행을 신뢰하지 않는다.** `encodeURIComponent`가 `\n`을 `%0A`로 바꾸므로 현재는 안전하다. **인코딩을 빼는 리팩터링을 하지 않는다.**

**규칙 13 — URL 길이 한계를 의식한다.** 직원 수가 늘면 `mailto:` URL이 OS 명령줄 길이 한계를 넘어 본문이 잘리거나 메일 앱이 안 열릴 수 있다. **보안이 아니라 신뢰성 항목이지만 같은 코드에서 발생한다.** V-03대로 본문에서 연락처를 빼면 길이도 함께 준다.

### 4-4. API 라우트 입력 검증

**규칙 14 — 요청 body를 스프레드해서 저장하지 않는다.**

```ts
// ❌ 지금 코드 (src/app/api/log/route.ts:23)
const record = { ...body, at: new Date().toISOString() };

// ✅ 화이트리스트로 재구성
const ALLOWED_EVENTS = new Set([
  "view", "training_start", "critical_confirm", "training_complete",
  "survey", "prep_view", "prep_check", "prep_scale",
  "recipe_view", "recipe_scale",
]);

const str = (v: unknown, max = 200) =>
  typeof v === "string" ? v.slice(0, max) : undefined;
const num = (v: unknown) =>
  typeof v === "number" && Number.isFinite(v) ? v : undefined;

// ★ 이 두 줄이 빠지면 ALLOWED_EVENTS는 선언만 되고 아무것도 막지 못한다.
//   V-04가 "더 아프다"고 한 헤드라인 결함(지표 위조)이 그대로 남는다. (규칙 16)
const ev = typeof body.event === "string" ? body.event : "";
if (!ALLOWED_EVENTS.has(ev))
  return Response.json({ ok: false, error: "unknown event" }, { status: 400 });

const record = {
  event: ev,
  sessionId: str(body.sessionId, 64),
  positionSlug: str(body.positionSlug, 64),
  taskId: str(body.taskId, 64),
  runId: str(body.runId, 64),
  durationSec: num(body.durationSec),
  confirmedCount: num(body.confirmedCount),
  askedSenior: str(body.askedSenior, 32),
  at: new Date().toISOString(),   // 항상 마지막 — 클라이언트가 덮어쓰지 못하게
};
```

**규칙 15 — 크기 상한을 `json()` 이전에 건다.**

```ts
const raw = await request.text();
if (raw.length > 4096) return new Response(null, { status: 413 });
let body: Record<string, unknown>;
try { body = JSON.parse(raw); } catch {
  return Response.json({ ok: false, error: "invalid json" }, { status: 400 });
}
if (typeof body !== "object" || body === null || Array.isArray(body)) {
  return Response.json({ ok: false, error: "invalid body" }, { status: 400 });
}
```

**규칙 16 — `event`가 화이트리스트에 없으면 400.** 조용히 버리지 않는다. 400을 주면 클라이언트 버그가 드러난다.
**산문으로만 적으면 구현에서 빠진다** — 규칙 14 블록의 `ALLOWED_EVENTS.has(ev)` 두 줄이 이 규칙의 실체다. `ALLOWED_EVENTS`를 선언해 놓고 참조하지 않으면 크기 상한·타입 가드·필드 화이트리스트는 들어오는데 **`event` 값 검증만 빠진 채로 통과한다.**

**규칙 17 — `at`은 항상 서버가 찍고 스프레드 뒤에 둔다.** 현재 코드도 순서상 서버 값이 이기지만, 화이트리스트 방식으로 바꾸면 구조적으로 보장된다.

**규칙 18 — 쓰기 실패를 조용히 삼키지 않는다.** `catch {}` 안에 최소한 `console.warn`. 사용자에게 노출하지 않는 것과 운영자에게 숨기는 것은 다르다.

**규칙 19 — 레이트 리밋.** 최소한 IP당 분당 상한. Vercel이면 그 플랫폼 기능을, 자체 호스팅이면 인메모리 카운터라도.

**규칙 20 — 파일 append는 상한 + 로테이션.** 또는 Supabase 이관 시 **컬럼을 고정해 임의 필드 저장이 구조적으로 불가능하게** 한다.

**규칙 21 — 읽기 전용 라우트도 인증 뒤에 둘지 판단한다.** `/api/media`는 파라미터가 없어 경로 탈출이 불가능하지만, **열거 자체가 정보다.** 개발 전용으로 제한하거나(`process.env.NODE_ENV !== "production"` 시 404) 게이트 뒤로.

**규칙 22 — 개발 중 바인딩 축소.** `next dev --hostname 127.0.0.1`. 현재 `0.0.0.0:3000` 바인딩 + Windows 방화벽이 `node.exe`를 **LocalPort=Any, Profile=Public, Allow**로 명시 허용하고 있고 현재 네트워크가 Public이다 — "카페 와이파이의 아무나"는 가정이 아니라 현재 설정이다.

### 4-5. 비밀 관리

**규칙 23 — `.gitignore`는 글롭으로.** `.env*` + `!.env.example`. 정확 파일명 나열은 반드시 빠뜨린다(V-11).

**규칙 24 — `NEXT_PUBLIC_` 접두사의 의미를 오해하지 않는다.**

| 접두사 | 어디까지 가는가 | 넣어도 되는 것 |
|---|---|---|
| `NEXT_PUBLIC_*` | **빌드 시 클라이언트 번들에 문자열로 인라인된다.** 브라우저에서 view-source로 읽힌다 | 사이트 URL, Supabase **anon** key, 공개 설정값 |
| 접두사 없음 | 서버(RSC·Route Handler·middleware)에서만 | service_role key, API 키, DB 접속 정보, **`STORE_PIN_SECRET`(PIN 세션 쿠키 서명 키, §5-2 3단계)** |

**PIN 게이트를 붙이는 순간 이 표에 실제로 걸리는 값이 생긴다.** `STORE_PIN_SECRET`에 `NEXT_PUBLIC_`을 붙이면 서명 키가 브라우저 번들에 인라인되고, **누구나 유효한 `sop_store` 쿠키를 만들어 게이트를 통과한다.** 접두사 하나로 게이트 전체가 무효화되는 유일한 값이다.

**`NEXT_PUBLIC_`은 "공개해도 된다"가 아니라 "공개된다"다.** 붙이는 순간 비밀이 아니게 된다. 되돌리려면 키를 폐기해야 한다.
`.env.example:7`의 `SUPABASE_SERVICE_ROLE_KEY`에 접두사가 **의도적으로 빠져 있는 것**은 올바른 설계다. 이 상태를 유지한다.

**규칙 25 — service_role key는 서버 코드에서만, 그것도 최소 범위로.** RLS를 완전히 우회하는 마스터 키다. `src/lib/repo.ts`는 `import fs from "node:fs"`를 쓰는 **서버 전용 파일**이고 `"use client"` 파일 중 이를 import하는 것이 0건이다 — Supabase 전환 시 이 경계를 유지하면 anon key가 브라우저에 갈 이유조차 없다.

**규칙 26 — 키를 파일로 만들지 않는다.** Vercel 프로젝트 환경변수 UI에만 넣는다. 로컬은 `.env.local`(이미 ignore됨) 하나만 쓴다.

**규칙 27 — 키 발급 전에 `.gitignore` 수정을 먼저 커밋한다.** 순서가 전부다.

### 5-2. 매장 PIN 잠금 설계

#### 왜 클라이언트 검사만으로는 무의미한가

**실측으로 확인한 사실:** `curl http://localhost:3000/r/shokupan` (23,291 bytes) 응답 **본문**에 배합비가 그대로 있다 — 강력분 2000g, 물 1200g, 설탕 120g, 소금 40g, 이스트 40g, 버터 120g. 더구나 `self.__next_f.push` RSC flight 페이로드에 원본 JSON이 직렬화돼 있다:

```
{"id":"rec-shokupan","slug":"shokupan",...,
 "ingredients":[{"name":"강력분","amount":2000,"unit":"g",...}]}
```

**즉 화면을 가려도 데이터는 이미 도착해 있다.**

| 잘못된 방식 | 왜 실패하는가 |
|---|---|
| `if (input === "1234")` 를 React 컴포넌트에 | PIN이 JS 번들에 박혀 view-source로 읽힌다 |
| 클라이언트 오버레이로 화면 가리기 | **위 실측대로 데이터가 이미 본문에 있다.** DevTools 없이도 `curl` 한 줄 |
| 페이지 컴포넌트 안에서 쿠키 검사 | `generateStaticParams()`가 있어 빌드타임 프리렌더된다 → SSG가 깨진다 |
| 단일 파일 HTML에 PIN | **원리적으로 불가능.** `매장수첩.html:313 const DATA =`에 데이터가 인라인이다. 파일 소지 = 데이터 소지 |

이 앱은 상태 관리가 전부 localStorage라 **구현자가 클라이언트 게이트를 택할 개연성이 높다.** 추상적 경고가 아니라 실제로 밟기 쉬운 함정이다.

#### 올바른 설계 — 순서대로

**0단계. `public/app.html` 삭제.** ✅ **이행 완료 (`528a75b`).** 정적 우회 경로를 먼저 없앤다. 미들웨어 matcher는 확장자 있는 경로를 흔히 제외하므로(`'/((?!api|_next/static|_next/image|.*\..*).*)'`) 이 파일이 남아 있으면 게이트를 그냥 지나간다. **0단계를 하면 이 고민 자체가 사라진다.**

**1단계. 루트를 공개 화면과 관리 화면으로 분리한다. 이 결정이 PIN 구현보다 먼저다.**
현재 `src/app/page.tsx`가 공개 대상(체크리스트 입구)과 잠금 대상(레시피 목록·근무표 입구)을 한 화면에 렌더한다. 루트를 공개로 두면 잠금 대상 목록이 새고, 루트를 잠그면 카톡 링크 흐름이 깨진다.
**단, 흔히 말하는 "MVP 전제가 깨진다"는 딜레마는 실제로 없다.** 카톡 공유 대상은 `/p/[slug]`이고 이건 자체 `generateStaticParams`와 카톡 미리보기용 openGraph 메타(`:25-40`)를 가진 **독립 라우트**다. 신입은 `/`를 거치지 않는다.
→ **정답: `/p/[slug]`는 공개 유지, `/`와 `/r`·`/prep`·`/roster`·`/shoot`는 게이트 뒤로.**

**2단계. `src/middleware.ts`로 게이트한다. 쿠키의 "존재"가 아니라 "값"을 검증한다.**

> ⚠️ **이 절이 위에서 경고한 함정을 서버 쪽에서 그대로 반복하기 쉬운 자리다.**
> `if (req.cookies.get("sop_store")) next()` 는 게이트가 아니다 — `req.cookies.get()`은
> **값이 빈 문자열이어도 객체를 반환하므로 항상 truthy**다. 즉
> `curl -b "sop_store=x" https://<host>/roster` 한 줄로 통과한다.
> **쿠키 값이 위조 불가해야 게이트다.** 서명(HMAC)한 값만 통과시킨다.

```ts
// src/middleware.ts  — Edge 런타임이므로 Web Crypto를 쓴다 (node:crypto 불가)
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

const SECRET = process.env.STORE_PIN_SECRET;  // NEXT_PUBLIC_ 금지 (§4-5 규칙 24)

/** 쿠키 형식: "<exp>.<base64url(HMAC-SHA256(exp))>" — exp는 만료 epoch(초) */
async function verify(token: string | undefined): Promise<boolean> {
  if (!token || !SECRET) return false;
  const [exp, sig] = token.split(".");
  if (!exp || !sig) return false;
  if (!Number.isFinite(Number(exp)) || Number(exp) * 1000 < Date.now()) return false;

  const key = await crypto.subtle.importKey(
    "raw", new TextEncoder().encode(SECRET),
    { name: "HMAC", hash: "SHA-256" }, false, ["sign"],
  );
  const mac = await crypto.subtle.sign("HMAC", key, new TextEncoder().encode(exp));
  const want = btoa(String.fromCharCode(...new Uint8Array(mac)))
    .replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");

  if (want.length !== sig.length) return false;      // 길이가 같을 때만 상수시간 비교
  let diff = 0;
  for (let i = 0; i < want.length; i++) diff |= want.charCodeAt(i) ^ sig.charCodeAt(i);
  return diff === 0;
}

export async function middleware(req: NextRequest) {
  if (await verify(req.cookies.get("sop_store")?.value)) return NextResponse.next();
  const url = req.nextUrl.clone();
  url.pathname = "/unlock";
  url.searchParams.set("next", req.nextUrl.pathname);  // 경로만. 쿼리는 넘기지 않는다
  return NextResponse.redirect(url);
}

export const config = {
  // /p/* (공개 체크리스트), /unlock, /api/unlock 은 제외
  matcher: ["/", "/r/:path*", "/prep/:path*", "/roster", "/shoot"],
};
```

**검증:** 붙인 뒤 `curl -b "sop_store=x" -i http://localhost:3000/roster`가 **307로 `/unlock`에 튕기는지** 확인한다. 200이 나오면 게이트가 아니다.

**3단계. PIN 검증과 쿠키 발급은 `POST /api/unlock`에서만.**

| 항목 | 규칙 |
|---|---|
| 저장 | PIN 원문 저장 금지. **argon2id 또는 bcrypt 해시** |
| 비교 | 상수시간 비교 (해시 라이브러리가 제공하는 verify 사용) |
| **쿠키 값** | **위조 불가해야 한다.** PIN 검증에 성공하면 `/api/unlock`이 만료시각을 **HMAC-SHA256으로 서명**해 `"<exp>.<sig>"` 형태로 발급하고, 미들웨어는 **서명과 만료를 검증한 뒤에만** 통과시킨다(2단계 코드). **"쿠키가 있으면 통과"는 게이트가 아니다** |
| 서명 비밀 | `STORE_PIN_SECRET` — **`NEXT_PUBLIC_` 접두사 없는 환경변수**(§4-5 규칙 24). 32바이트 이상 랜덤, Vercel 환경변수 UI에만 넣는다(규칙 26). 교체하면 전 매장이 다시 PIN을 입력하게 된다 |
| 시도 제한 | **필수.** 4자리 = 후보 1만 개. 레이트리밋이 없으면 해시 저장도 무의미하다. IP + 쿠키 기준, 실패 5회 후 지수 백오프 |
| 자릿수 | ❓ **미정.** 코드·문서 어디에도 자릿수 명시가 없다(`4자리\|네 자리\|6자리` grep 0건). **6자리 이상 권장** — 4자리는 시도 제한에 전적으로 의존하게 된다 |
| 세션 쿠키 속성 | `httpOnly; Secure; SameSite=Lax; Max-Age=<영업일 단위>`. **속성은 값 위조를 막지 못한다** — 위 서명과 함께여야 의미가 있다 |
| **금지** | PIN 원문을 **쿠키·localStorage·URL 쿼리에 절대 넣지 않는다.** 쿼리는 서버 액세스 로그와 Referer로 샌다 |

**4단계. PIN 세션이 생기면 새 위협이 열린다.** 그때 처음으로 클릭재킹·CSRF 전제가 성립한다 → **`frame-ancestors 'none'`과 `SameSite=Lax`를 같은 티켓에 묶는다.**

**5단계. PIN의 한계를 문서에 적어둔다.** PIN은 매장 전원이 같은 값을 알게 되므로 **"누가 열람했는가"를 남길 수 없다.** 근무표(제3자 개인정보)에는 계정 단위 분리가 필요한지 Supabase 이관 시 재검토한다.

### 5-3. Supabase 연결 시 필수 사항

#### anon key의 성질

| | anon key | service_role key |
|---|---|---|
| 어디까지 가는가 | `NEXT_PUBLIC_` 접두사 → **브라우저에 인라인. 비밀이 아니다** | 서버 전용 |
| RLS | **적용된다** | **완전히 우회한다 (마스터 키)** |
| 유출 시 | RLS가 제대로면 피해 제한적 | **DB 전체 읽기·쓰기·삭제** |

출처: <https://supabase.com/docs/guides/api/api-keys>

**anon key는 "숨겨야 하는 비밀"이 아니라 "RLS가 없으면 DB 덤프 도구"다.** anon key + RLS off = 인증 없는 공개 DB API. 이게 이 프로젝트에서 가장 조용히 터질 수 있는 지점이다.

#### 이 프로젝트의 마이그레이션 경로는 서버측이다 — 그 성질을 이용하라

`src/lib/repo.ts:1`이 `import fs from "node:fs"`다 → **물리적으로 클라이언트 번들에 못 들어간다.** `"use client"` 파일 중 이를 import하는 것이 **0건**이고, `repo`를 쓰는 10개 파일은 전부 서버 컴포넌트다(실측). 그리고 `03_ERD.md` 9절 단계 1이 명시한 경로가 "`repo.ts` 12개 함수 **본문만** 쿼리로 교체, 시그니처 유지"다.

→ **이대로 가면 DB 접근이 서버에 남고 anon key가 브라우저에 갈 이유조차 없다.** "anon key 번들 노출 → curl 덤프"는 이 코드베이스의 기본 경로가 아니라 **선택 가능한 실수**다. 그 실수를 하지 않는 것이 첫 번째 방어다.

쓰기 경로도 서버 패턴이 이미 있다 — `src/app/api/log/route.ts`가 Route Handler다.

#### RLS — 로그인이 없어도 쓸 수 있다

**"로그인이 없으면 RLS를 쓸 수 없다"는 틀렸다.** RLS 정책은 `auth.uid()`만 쓰는 게 아니라 Postgres 정책 표현식 전체를 쓸 수 있고, 최소 두 가지 경로가 있다:
- **익명 로그인** — 회원가입 없이 실제 `auth.uid()`가 발급된다. <https://supabase.com/docs/guides/auth/auth-anonymous>
- **서드파티/커스텀 JWT** — 매장 PIN 검증 후 서버가 JWT를 발급. <https://supabase.com/docs/guides/auth/third-party/overview>

즉 "회원가입 없이"라는 MVP 전제와 RLS는 배타 관계가 아니다.

#### 착수 전 체크리스트

| # | 항목 | 왜 |
|---|---|---|
| 1 | `.gitignore` `.env*` 먼저 커밋 (V-11) | 첫 키 발급 **전에**. 순서가 전부 |

| 4 | anon 롤에 `insert/update/delete` 기본 차단 | 읽기만 열고 쓰기는 서버 경유 |

### 5-4. 보안 헤더 설정안

`next.config.ts` 전체를 아래로 교체한다.

> ⚠️ **`'unsafe-eval'` dev 분기를 빼면 `npm run dev` 화면이 죽는다. 이게 이 절에서 가장 중요한 줄이다.**
> `headers()`는 **dev 서버에도 적용된다.** 그런데 `next dev`의 클라이언트 청크는 `eval-source-map`
> devtool로 빌드되어 모듈을 `eval()`로 감싼다 — 실측: `.next/static/chunks/app/page.js` 첫 줄이
> `ATTENTION: An "eval-source-map" devtool has been used ... It uses "eval()" calls`이고 같은 파일에
> `eval(` 13회, `.next/static/development/` 디렉터리 존재.
> `script-src`에 `'unsafe-eval'`이 없으면 이 청크 실행이 CSP에 막혀 **하이드레이션과 클릭 동작이 전부 죽는다.**
> **9/18 라이브 시연 경로가 `npm run dev`다.** 아래처럼 환경 분기를 넣거나, 넣지 않을 거라면
> 이 설정을 **정식 배포 빌드에만** 적용할 것.

```ts
import type { NextConfig } from "next";

const dev = process.env.NODE_ENV === "development";

/**
 * CSP 주의 — 'unsafe-inline'을 script-src에 둔 이유:
 *   App Router가 RSC 페이로드를 인라인 <script>로 주입한다.
 *   정식 배포 후 middleware.ts에서 요청별 nonce를 발급해
 *   'nonce-XXX' 'strict-dynamic' 으로 바꾸고 'unsafe-inline'을 제거할 것.
 *
 * 'unsafe-eval' 은 dev 전용이다 — next dev 청크가 eval-source-map을 쓴다.
 *   프로덕션 빌드에는 붙지 않으므로 배포본 CSP는 약해지지 않는다.
 *
 * 폰트 — Next 앱은 외부 폰트를 쓰지 않으므로 font-src 'self' 로 충분하다.
 *   단일 파일 버전(presentation/)은 이 설정의 적용 대상이 아니다.
 */
const csp = [
  "default-src 'self'",
  "script-src 'self' 'unsafe-inline'" + (dev ? " 'unsafe-eval'" : ""),
  "style-src 'self' 'unsafe-inline'",
  "img-src 'self' data: blob:",
  "media-src 'self'",
  "font-src 'self'",
  "connect-src 'self'",
  "frame-ancestors 'none'",
  "form-action 'self'",
  "base-uri 'self'",
  "object-src 'none'",
  "upgrade-insecure-requests",
].join("; ");

const nextConfig: NextConfig = {
  // 체크리스트 사진을 외부 호스트로 옮기면 여기에 도메인을 추가한다.
  images: { remotePatterns: [] },

  // X-Powered-By: Next.js 를 내보내지 않는다
  poweredByHeader: false,

  async headers() {
    return [
      {
        // 정적 파일(/app.html 등)까지 포함해 전 경로에 적용된다
        source: "/:path*",
        headers: [
          { key: "Content-Security-Policy", value: csp },
          { key: "X-Content-Type-Options", value: "nosniff" },
          { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
          { key: "X-Frame-Options", value: "DENY" },
          {
            key: "Permissions-Policy",
            // 촬영 모드를 만들면 camera=(self) 로 되돌릴 것
            value:
              "camera=(), microphone=(), geolocation=(), payment=(), usb=()",
          },
          {
            key: "Strict-Transport-Security",
            value: "max-age=63072000; includeSubDomains",
          },
          {
            // D-007 미이행분(V-09) — 정적 파일까지 한꺼번에 덮는다
            key: "X-Robots-Tag",
            value: "noindex, nofollow",
          },
        ],
      },
    ];
  },
};

export default nextConfig;
```

**적용 시 주의:**

| 항목 | 내용 |
|---|---|
| `X-Robots-Tag` | **정식 서비스 시작 시 제거해야 한다.** 지금은 D-007(시연용 제한 배포)이 검색 차단을 조건으로 걸었기 때문에 넣는 것이다 |
| `unsafe-inline` | 임시다. nonce 전환 티켓을 남길 것 |
| `unsafe-eval` | **dev에서만 붙는다.** 빼면 `npm run dev` 화면이 CSP에 막혀 죽는다(위 경고). 프로덕션 빌드에는 안 붙으므로 배포본 CSP는 그대로다 |
| **적용 후 검증** | **`npm run dev`로 앱을 열어 브라우저 콘솔 CSP 위반 0건 + 클릭 동작 정상을 확인한다.** 이 확인 없이 발표 당일에 적용하지 말 것 |
| 단일 파일 버전 | **이 설정은 `presentation/*.html`에 적용되지 않는다.** Artifact 호스트가 자체 CSP로 서빙한다. 그리고 그 파일들은 인라인 `<script>`/`<style>` 블록과 다수의 `style="..."` 속성을 쓰므로(정적 파일에는 nonce 주입 불가) `unsafe-inline` 없이는 시연본이 깨진다 |
| `font-src 'self'` | ✅ **양쪽이 일치한다 (2026-09-07).** V-12를 링크 제거로 처리해 단일 파일도 외부 폰트를 안 쓴다 |
| 검증 | 배포 후 `curl -I <URL>`로 실제 응답 헤더 확인. ❓ Vercel이 HSTS를 자동으로 붙이는지는 배포본이 없어 미검증 |
