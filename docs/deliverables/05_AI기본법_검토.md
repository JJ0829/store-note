> ⛔ **이 판정은 2026-09-10 에 뒤집혔다. 위 머리말을 볼 것.** 아래는 2026-09-04 시점의 기록이다.

~~**판정: 현재 시점의 매장수첩는 「AI 기본법」상 인공지능사업자가 아니다. 따라서 이 법의 의무가 발생하지 않는다.**~~

> ⚠️ **"외부 네트워크 요청이 아예 없다"고 읽지 말 것.** 이 판정은 AI·추론 서버에 한정된다.

> AI 해당성 판정은 그대로 유지되지만, 개인정보 국외 이전 쟁점은 **별도로 살아 있다.**

다만 세 가지를 분명히 해둔다.

| # | 요지 | 상세 |
|---|---|---|
| 1 | **"AI로 개발했다" ≠ "AI 서비스다"** | 개발 도구로 생성형 AI를 쓴 것과 제품이 AI 기능을 제공하는 것은 규제상 완전히 다른 층위다. 이 구분을 발표에서 흐리면 안 된다. → §4, §7 |

## 3. 이 제품의 AI 해당성 판정 ★ 핵심

### 3.1 판정

> **매장수첩는 실행 중 어떤 AI도 호출하지 않는다. 따라서 AI 기본법상 인공지능사업자에 해당하지 않는다.**

이건 "아직 안 붙였다"는 계획상의 진술이 아니라 **코드로 확인된 사실**이다. 아래가 근거다.

### 3.2 근거 1 — AI API 키가 설정 파일에 주석으로만 존재하고, 사용처가 없다

`.env.example` 전문 (파일 전체가 10줄이라 그대로 옮긴다):

```bash
# 공유 링크에 쓰이는 절대 URL (카카오톡 미리보기 og:image 생성에 필요)
NEXT_PUBLIC_SITE_URL=http://localhost:3000

# --- 아래는 2단계(Supabase 연결) 때 채우면 됨 ---
# NEXT_PUBLIC_SUPABASE_URL=
# NEXT_PUBLIC_SUPABASE_ANON_KEY=
# SUPABASE_SERVICE_ROLE_KEY=

# --- 3단계(AI 초안 생성) 때 ---
# ANTHROPIC_API_KEY=
```

확인 사항 두 가지.

| 확인 | 결과 |
|---|---|
| `ANTHROPIC_API_KEY`가 활성 상태인가 | ❌ 아니오. `#`으로 **주석 처리**되어 있고 값도 비어 있다. 주석 헤더가 "**3단계(AI 초안 생성) 때**"라고 명시 — 즉 미래 계획을 위한 자리표시자다 |
| 코드에서 이 키를 읽는 곳이 있는가 | ❌ **없다.** `src/`, `data/`, `public/`, `presentation/`, `package.json`, `next.config.ts` 전체를 `ANTHROPIC` / `anthropic` 으로 검색해 **일치 0건** |

`.env.local`도 `.env.example`과 내용이 동일하다 (둘 다 353바이트). 즉 로컬 개발 환경에도 실제 AI 키가 들어가 있지 않다.

> **자리표시자와 실사용의 차이가 판정의 전부다.** 주석 처리된 키는 코드가 아니다. 실행되지 않고, 참조되지 않고, 네트워크를 발생시키지 않는다.

### 3.3 근거 2 — 의존성에 AI SDK가 없다

`package.json` 의존성 전량:

| 구분 | 패키지 |
|---|---|
| dependencies | `next` ^15.1.0, `react` ^19.0.0, `react-dom` ^19.0.0 — **총 3개** |
| devDependencies | `@tailwindcss/postcss`, `tailwindcss`, `typescript`, `@types/node`, `@types/react`, `@types/react-dom` — 전부 빌드·타입 도구 |

`@anthropic-ai/sdk`, `openai`, `langchain` 등 **AI 관련 패키지는 하나도 없다.** 런타임 의존성이 프레임워크 3개뿐이라 AI 호출이 물리적으로 불가능하다.

### 3.4 근거 3 — React 앱(`src/`)에서 외부로 나가는 요청이 없다 (단, 정적 HTML 사본은 예외)

> ⚠️ **먼저 검증 범위를 명시한다.** 아래 (1)의 판정 범위는 **`src/`(Next.js React 앱)에 한정**된다.
> 이 문서 초판은 `src/`만 grep해 놓고 결론을 "이 제품"으로 일반화했다. **그건 틀렸다.**
> Next.js는 `public/` 하위를 루트 경로로 그대로 서빙하므로, `/app.html`에 접속하면
> 실제로 외부 요청이 발생한다. (2)에 따로 적는다.

#### (1) `src/` — 외부 요청 0건 ✅

`src/` 전체에서 `fetch(` / `XMLHttpRequest` / `axios` / `WebSocket` / `sendBeacon` 을 검색한 결과, 호출 지점은 **5곳뿐이고 전부 자기 자신(same-origin)을 향한다.**

| 호출 위치 | 대상 | 성격 |
|---|---|---|
| `src/components/ChecklistView.tsx:36` | `/api/log` | 자체 API |
| `src/components/PrepView.tsx:42` | `/api/log` | 자체 API |
| `src/components/RecipeDetail.tsx:33` | `/api/log` | 자체 API |
| `src/components/TrainingMode.tsx:32` | `/api/log` | 자체 API |
| `src/lib/mediaProbe.ts:35` | `/api/media` | 자체 API |

`src/` 전체의 절대 URL 문자열도 `src/app/p/[slug]/page.tsx:27`의 `http://localhost` 하나가 전부다.
폰트도 외부에서 불러오지 않는다 — `src/app/layout.tsx`에 `next/font` 사용이 없고,
`src/app/globals.css:3-6`의 `--font-sans`는 기기에 설치된 폰트 스택만 나열한다.

그리고 그 두 자체 API도 AI와 무관하다.

| API | 하는 일 | 근거 |
|---|---|---|
| `/api/log` | 요청 본문에 타임스탬프를 붙여 `data/events.jsonl`에 한 줄 덧붙임. `fs.appendFile`만 씀 | `src/app/api/log/route.ts` |
| `/api/media` | `public/media/` 폴더의 파일 이름 목록을 반환. `fs.readdir`만 씀 | `src/app/api/media/route.ts` |

#### (2) 정적 HTML 사본 — Google Fonts로 외부 요청이 나간다 ⚠️

단일 파일 버전 3개가 모두 머리에 Google Fonts를 불러오는 `<link>` 3줄을 가지고 있다.

| 파일 | 줄 | 내용 | 외부에서 접근 가능한가 |
|---|---|---|---|
| `public/app.html` | 11-13 | `preconnect https://fonts.googleapis.com` / `preconnect https://fonts.gstatic.com` / `stylesheet https://fonts.googleapis.com/css2?family=IBM+Plex+Mono…&family=IBM+Plex+Sans+KR…` | ✅ **예.** Next.js가 `public/`을 루트로 서빙 → `/app.html`로 열린다. 링크는 없지만 주소를 직접 입력하면 열린다 (`02_화면설계서.md:102` X-01) |
| `presentation/매장수첩.html` | 11-13 | 위와 동일 (`public/app.html`과 **바이트 동일**, md5 `85716f76…`) | ✅ **예.** Claude Artifact로 시연 게시된 것이 이 파일이다 (`04_라이선스감사.md:556`) |
| `presentation/app.html` | 2-4 | 위와 동일 (`<head>` 없는 조각본) | ⬜ 저장소 내부 파일 |

즉 **열람자의 IP·User-Agent·Referer가 Google LLC(미국)로 전달된다.**
동일 사실을 `10_개인정보처리방침.md:126`·`:240-241`과 `04_라이선스감사.md:556`이 이미 기록해 두었다.

#### (3) 종합 — AI 판정에는 영향 없음, 개인정보 판정에는 영향 있음

> **AI·추론 서버로는 요청을 보내지 않는다.** 그래서 §3.1의 AI 해당성 판정은 그대로 유지된다.
> Google Fonts는 폰트 CDN이지 AI 서비스가 아니다.
>
> **그러나 "어떤 제3자 서버로도 요청을 보내지 않는다"는 서술은 사실이 아니므로 철회한다.**
> 폰트 CDN 경유로 IP가 국외로 나가는 문제는 **개인정보 국외 이전 쟁점**이고 별도로 살아 있다.
> → §5.3, 그리고 `10_개인정보처리방침.md` 조치 **#5(시연 게시본의 `<link>` 3줄 제거)**.

### 3.5 근거 4 — 제품 문서도 AI 기능을 "미구현"으로 기록하고 있다

## 4. 개발 도구로서의 AI vs 제품으로서의 AI

이 문서에서 가장 오해받기 쉬운 지점이라 따로 절을 뗀다.

### 4.1 사실관계

이 프로젝트는 **생성형 AI(Claude)를 코드 작성 도구로 사용해서 개발됐다.** 감출 일도 아니고 실제로 흔적도 남아 있다 — git 커밋 15건에 `Co-Authored-By: Claude` 트레일러가 붙어 있다.

그러나 그 사실은 **제품의 성질을 바꾸지 않는다.**

### 4.2 두 층위의 구분

| 구분 | 개발 도구로서의 AI | 제품으로서의 AI |
|---|---|---|
| 무엇인가 | 개발자가 코드를 짤 때 AI의 도움을 받음 | 최종 이용자가 제품을 쓸 때 AI가 동작함 |
| 언제 일어나는가 | **개발 시점** (2026년 8~9월, 개발자 PC) | **실행 시점** (매장 태블릿, 이용자 앞) |
| 이용자가 AI와 접촉하는가 | ❌ 아니오 | ✅ 예 |
| 산출물 | 사람이 검토·수정한 소스 코드 | AI가 실시간 생성한 결과물 |
| 매장수첩 해당 | ✅ **예** | ❌ **아니오** |
| AI 기본법 규율 대상 | ❌ 아니오 | ✅ 예 |

### 4.3 비유

목수가 전동 드릴로 의자를 만들었다고 해서 그 의자가 전동 공구가 되지는 않는다. **AI 기본법이 규율하는 것은 의자가 아니라 전동 공구를 파는 사람이다.**

매장수첩는 AI가 만든 의자다. 의자 안에 드릴이 들어 있지 않다. (§3에서 드릴이 없다는 것을 코드로 확인했다.)

### 4.4 개발 도구 사용에서 실제로 발생하는 쟁점

AI 기본법 의무는 안 생기지만, 다른 쟁점은 생긴다. 무시하면 안 된다.

| 쟁점 | 내용 | 현재 상태 | 조치 |
|---|---|---|---|
| **저작권 귀속** | 저작권법 제2조 제1호상 저작물은 **인간**의 창작적 표현. 인간의 창작적 개입 없는 AI 산출물은 저작권 등록 불가 (문체부 안내서, 2023-12-27) | 사람이 요구사항을 정의하고 결과를 검토·수정·재지시했으므로 창작적 개입은 있다고 본다 | 정부지원사업 협약 시 IP 귀속 조항 확인. ❓ **확인 필요** — 지원사업 공고문의 산출물 권리 조항 |
| **코드 출처·라이선스** | AI가 생성한 코드에 타인의 라이선스 코드가 섞였을 가능성 | **기술 검토 완료.** `04_라이선스감사.md`(2026-09-03, 기준 커밋 `234346e`) 상태 = "초안 — 기술 검토 완료 / 법률 검토 미실시". 같은 문서가 **코드 복사·붙여넣기 여부는 ❓ 확인 필요로 남겨 두었다**(`04:553`, 12절) | 법률 검토는 미실시. `04_라이선스감사.md` 12절의 미확인 항목을 따라갈 것 |
| **입력 데이터 유출** | 개발 중 AI에 붙여넣은 내용에 개인정보·영업비밀이 포함됐는지 | 시드 데이터는 가상. 다만 근무표 실데이터를 붙여넣지 않았는지 ❓ **확인 필요** | §6-B 원칙 적용 |
| **정확성 책임** | **결함 책임은 개발자·사업자가 진다는 전제로 작업한다.** "AI가 썼으니 책임이 줄어든다"는 전제는 두지 않는다 | 설계·운영 원칙으로 채택 | `06_보안설계.md`, `08_테스트자동화.md` |

> ⚠️ **'정확성 책임' 행은 법적 단정이 아니다.** 초판은 "결함 책임은 **전적으로** 개발자·사업자에게 있다"고
> 썼는데, **근거 법령·조항·출처를 하나도 붙이지 못했다.** 책임 귀속은 계약 내용·제조물책임·민법상
> 다툼의 여지가 큰 명제이고, 조문을 확인하지 못한 채 "전적으로"라고 쓸 수 없다.
> 그래서 **법적 단정을 빼고 우리가 지킬 원칙으로 낮췄다.** 조문 확인은 §10 #13으로 넘긴다.
> 발표에서도 "책임은 저에게 있다는 **전제로 작업했다**"까지만 말할 것(§8.4).

### 5.4 예비 검토 — 만약 인공지능사업자가 된다면 고영향 AI인가?

제33조 제1항은 모든 인공지능사업자에게 "고영향 해당 여부를 사전 검토"할 의무를 지운다. 지금은 해당 없지만, AI 기능 추가 시를 대비해 미리 답을 내둔다.

**예비 판정: 고영향 인공지능에 해당하지 않는다고 판단한다. 단 조건이 붙는다.**

| 고영향 판단 요소 | 매장수첩(AI 촬영 목록 생성 기준) | 평가 |
|---|---|---|
| 사람의 생명·신체 안전에 중대한 영향 | 촬영할 항목 목록을 제안할 뿐. 식품안전 판단을 대신하지 않음 | ⬜ 해당 없음 |
| 기본권에 중대한 영향 | 개인에 대한 결정을 하지 않음 | ⬜ 해당 없음 |
| 채용·인사 결정 | ❌ 하지 않음 | ⬜ 해당 없음 |
| 대출·신용 평가 | ❌ 하지 않음 | ⬜ 해당 없음 |

> ⚠️ **조건:** 이 판정은 "AI가 촬영 목록만 만든다"는 전제에 붙어 있다. **AI가 직원의 체크 기록이나 근무 데이터를 평가하는 기능이 생기면 채용·인사 영역에 근접하고 판정이 달라질 수 있다.** §6-A가 이걸 막기 위한 원칙이다.
>
> 고영향 영역이 "10개 영역"으로 규정되어 있다는 2차 출처가 있으나 **전체 목록 원문은 ❓ 확인 필요.** AI 기능 착수 시 시행령 별표를 직접 대조할 것.

## 6. 향후 AI 기능 추가 시 발생하는 의무

### 6.0 기준이 되는 계획

`CLAUDE.md`에 확정된 결정으로 기록되어 있다.

> **AI의 역할은 텍스트 초안이 아니라 촬영 목록 생성이다.** 포지션명 넣으면 "이 18개를 찍으세요"가 나오고 폰 들고 한 바퀴.

즉 예상 동작은 이렇다.

| 단계 | 내용 |
|---|---|
| 입력 | 포지션명 (예: "바리스타", "제빵 오픈") |
| 처리 | 외부 LLM API 호출 (`ANTHROPIC_API_KEY` 사용 개시) |
| 출력 | 촬영해야 할 항목 목록 (텍스트) |
| 이용자 | 점주 (사장님 화면) |

### 6.1 이 순간 발생하는 신분 변화

| 항목 | 변화 전 | 변화 후 |
|---|---|---|
| 법적 지위 | 해당 없음 | **인공지능이용사업자** (외부 AI를 이용해 AI 제품·서비스 제공) |
| AI 종류 | — | **생성형 인공지능** (텍스트 콘텐츠 생성) |
| 제31조 제1항 | 미적용 | ✅ **적용** — 사전 고지 |
| 제31조 제2항 | 미적용 | ⚠️ **적용 검토 필요** — 생성물 표시 |
| 제33조 제1항 | 미적용 | ✅ **적용** — 고영향 해당 여부 검토 (§5.4 갱신) |
| 개인정보 국외이전 | 해당 없음 | ⚠️ **검토 필요** — API 서버가 국외인 경우 |

### 6.2 어떤 표시·고지가 필요한가

#### (1) 사전 고지 — 제31조 제1항 [필수]

제품·서비스가 생성형 AI에 기반해 운용된다는 **사실을 이용자에게 미리** 알려야 한다. 2차 출처에 따르면 이행 방법은 이용약관·계약서 기재, 서비스 화면 표시, 안내문 게시 등이다.

**구현안 (3중 배치)**

| 위치 | 문구(안) | 파일 |
|---|---|---|
| 기능 진입 버튼 옆 | "AI가 촬영 목록 초안을 만듭니다" | `src/app/shoot/page.tsx` 또는 신규 화면 |
| 기능 실행 직전 화면 | "포지션명을 외부 AI 서비스에 보내 목록을 생성합니다. 직원 이름·연락처는 전송되지 않습니다." | 동일 |
| 이용약관 | AI 기능 조항 신설 — 사용 사실, 제공 사업자, 한계, 책임 범위 | `09_이용약관.md` |

> **왜 3중인가:** 제31조 제1항 위반은 시정명령 없이 **직접 과태료**가 붙는 유형이라는 2차 출처가 있다(1차 500만원). 가장 방어적으로 갈 가치가 있다.

#### (2) 생성물 표시 — 제31조 제2항 [검토 필요]

**쟁점: 촬영 목록이 "AI 생성물"로서 표시 의무 대상인가?**

| 논거 | 방향 |
|---|---|
| 목록 텍스트도 생성형 AI가 만든 콘텐츠다 | 표시 필요 |
| 2차 출처상 "서비스 환경 내에서만 이용되는 경우"는 UI 표시·로고로 갈음 가능. 이 목록은 매장 밖으로 반출되지 않음 | 경량 표시로 충분 |
| 2차 출처상 **내부 업무용**은 투명성 고지 면제 가능(시행령 제23조 제4항 제2호로 언급되나 조문 ❓ 확인 필요) | 면제 가능성 |

**결론(잠정): 면제 가능성이 있더라도 표시한다.** 비용이 사실상 0이고, 면제 해석에 의존하는 것보다 안전하다.

**구현안**

| 방법 | 내용 |
|---|---|
| 화면 배지 | 생성된 목록 상단에 "AI 생성 초안" 배지 고정 |
| 데이터 필드 | 생성 항목에 `source: "ai"` 필드를 남겨, 사람이 수정하면 `source: "human"`으로 전환 |
| 편집 후 처리 | 점주가 수정·확정한 항목은 사람의 저작물로 다루되, 최초 생성 이력은 보존 |

> **주의:** 딥페이크 조항(제31조 제3항)은 텍스트 목록에는 해당하지 않는다. 다만 **AI로 이미지·영상을 생성하는 기능은 추가하지 않는 것을 원칙으로 한다.** 이 제품의 영상은 "가장 잘하는 사람의 실제 시연을 박제한 것"이 본질이고(`CLAUDE.md`), AI 합성 영상은 그 본질과 정면으로 충돌한다.

### 6.3 이용자에게 무엇을 알려야 하는가

고지 문구에 반드시 들어가야 할 항목.

| # | 항목 | 왜 |
|---|---|---|
| 1 | AI를 사용한다는 사실 | 제31조 제1항 |
| 2 | 어떤 AI 사업자의 서비스인지 | 제3자 제공 투명성 |
| 3 | 무엇이 전송되는지 (포지션명만) | 개인정보 우려 해소 |
| 4 | 무엇이 전송되지 않는지 (직원 이름·연락처·체크 기록) | 신뢰 확보 — 매장 입장에서 가장 궁금한 부분 |
| 5 | 결과가 **초안**이며 부정확할 수 있다는 것 | 정확성 한계 고지 |
| 6 | **최종 확인 책임은 점주에게 있다** | 식품위생·안전 판단을 AI에 위임하지 않음 |
| 7 | AI 기능을 쓰지 않아도 제품을 쓸 수 있다는 것 | 선택권 |

**문구 초안**

> 촬영 목록은 AI가 만든 **초안**입니다. 포지션명만 외부 AI 서비스로 전송되며, 직원 이름·연락처·체크 기록은 전송되지 않습니다.
> 목록이 우리 매장에 맞는지는 사장님이 확인하고 고쳐주세요. 위생·안전 기준의 최종 판단은 AI가 대신할 수 없습니다.
> 이 기능을 쓰지 않고 직접 목록을 만들어도 됩니다.

> ⚠️ **7번(선택권)은 법적 의무로 확인된 것이 아니다.** AI 기본법상 생성형 AI 이용 거부권 규정은 확인하지 못했다. ❓ **확인 필요.** 여기서는 법적 의무가 아니라 §7 윤리 원칙으로서 넣는다.

### 6.4 프롬프트·출력에 개인정보가 들어가지 않게 하는 설계 원칙

**이게 AI 기능 설계에서 가장 중요하다.** 근무표(`src/lib/roster.ts`)에 이미 이름·이메일·전화번호가 들어 있어서, 아무 생각 없이 "매장 컨텍스트"를 프롬프트에 넣으면 개인정보가 그대로 국외 API로 나간다.

#### 원칙 P1 — 허용 목록 방식 (Allow-list only)

프롬프트에 넣을 필드를 **명시적으로 열거**하고, 열거되지 않은 것은 전부 차단한다. 차단 목록 방식은 새 필드가 추가될 때 뚫린다.

| 구분 | 필드 |
|---|---|
| ✅ 전송 허용 | 포지션명, 메뉴명, 업종 구분(카페/베이커리), 항목 개수 |
| ❌ 전송 금지 | 직원 이름, 이메일, 전화번호, 근무 배정(`assign`), 체크 기록, `runId`, 매장 상호, 매장 주소, 레시피 배합비(**영업비밀**) |

#### 원칙 P2 — 객체 통째로 넘기지 않기

```
// ❌ 금지 — 무엇이 들어갈지 통제 불가
buildPrompt(rosterData)
JSON.stringify(staff)

// ✅ 필드를 하나씩 명시적으로 꺼낸다
buildPrompt({ position: position.name })
```

#### 원칙 P3 — 전송 직전 차단 게이트

API 호출 직전 한 곳에 검사 함수를 두고, 개인정보 패턴(이메일 `@`, 전화번호 숫자열, 저장된 직원 이름과의 일치)이 발견되면 **전송을 중단하고 실패시킨다.** 조용히 마스킹하지 말고 실패시켜야 개발 중에 발견된다.

#### 원칙 P4 — 레시피는 절대 전송하지 않는다

`CLAUDE.md`가 확정한 사항이다.

> 레시피는 공개 링크로 두면 안 된다. **영업비밀이다.**

공개 링크로도 안 되는 것을 외부 AI API로 보내는 건 더 안 된다. **레시피 배합비·수율은 AI 기능의 입력에서 원천 배제한다.**

#### 원칙 P5 — 출력도 검사한다

AI 출력에 실존 인물명처럼 보이는 것이 섞이면 화면에 렌더링하지 않는다. 촬영 목록에 사람 이름이 나올 이유가 없다.

#### 원칙 P6 — 로그에 프롬프트를 남기지 않는다

`/api/log`가 `data/events.jsonl`에 요청 본문을 통째로 기록한다 (`src/app/api/log/route.ts` — `{ ...body, at: ... }`). **AI 프롬프트나 출력을 이 엔드포인트로 보내면 안 된다.** 남길 거면 "ai_generate 호출됨 / 항목 수 18개" 같은 메타데이터만.

#### 원칙 P7 — 국외 이전 고지

API 서버가 국외에 있으면 개인정보 국외이전 쟁점이 생긴다. **P1~P4를 지켜 개인정보를 아예 안 보내면 이 쟁점 자체가 소멸한다.** 이것이 P1의 진짜 이유다. ❓ 개인정보를 보내지 않아도 별도 고지가 필요한지는 **확인 필요.**

#### 체크리스트 (AI 기능 PR 머지 전 필수)

| # | 확인 | 통과 |
|---|---|---|
| 1 | 프롬프트에 들어가는 필드가 코드에 명시적으로 열거되어 있는가 | ⬜ |
| 2 | 근무표 데이터(`roster.ts`)를 참조하는 경로가 없는가 | ⬜ |
| 3 | 레시피 배합비를 참조하는 경로가 없는가 | ⬜ |
| 4 | 전송 직전 차단 게이트가 있고 테스트가 있는가 | ⬜ |
| 5 | 프롬프트·출력이 `/api/log`로 흘러가지 않는가 | ⬜ |
| 6 | 사전 고지 문구가 화면에 있는가 (제31조 제1항) | ⬜ |
| 7 | "AI 생성 초안" 표시가 있는가 (제31조 제2항) | ⬜ |
| 8 | 이용약관에 AI 조항이 반영됐는가 | ⬜ |
| 9 | 개인정보처리방침이 갱신됐는가 | ⬜ |
| 10 | 고영향 해당 여부를 재검토했는가 (제33조 제1항, §5.4 갱신) | ⬜ |

## 7. AI 윤리 자체 점검표

과기정통부 「인공지능 윤리기준」(2020-12-22)의 10대 핵심요건을 **이 제품 맥락으로** 옮긴 것이다. 일반론이 아니라 주방·직원이라는 이 제품의 실제 조건에 맞췄다.

### 7.A 가장 중요한 원칙 — 사람을 평가·감시하는 데 쓰지 않는다 ★

**이 제품에는 구조적 위험이 하나 있다.** 이미 다음 데이터를 가지고 있거나 갖게 된다.

| 데이터 | 위치 | 인사평가로 전용될 위험 |
|---|---|---|
| 직원 이름·이메일·전화번호 | `src/lib/roster.ts` Staff | 개인 식별 |
| 근무 배정(누가 언제 일했는가) | `src/lib/roster.ts` Assign | 근태 추적 |
| 체크리스트 완료 기록 | localStorage / `/api/log` | 업무 수행 기록 |
| 교육 소요 시간 `durationSec` | `교육_완료` 이벤트 | **"이 신입은 남보다 느리다"로 읽힐 수 있음** |
| 설문 "선배에게 몇 번 물어봤나" | `설문_응답` 이벤트 | **"이 신입은 질문이 많다"로 읽힐 수 있음** |

이 넷을 직원 이름과 결합하면 **인사평가 시스템이 된다.** 그건 이 제품이 하려던 일이 아니다.

`CLAUDE.md`가 정의한 문제는 이것이다.

> **주방의 모든 기준이 사람 머릿속에 있다.**

**목표는 기준을 꺼내는 것이지 사람을 재는 것이 아니다.** 지표는 *제품이 효과가 있는가*를 검증하려고 모으는 것이지 *누가 일을 못하는가*를 가리려고 모으는 게 아니다.

#### 지켜야 할 선

| # | 원칙 | 구현 |
|---|---|---|
| E1 | **지표를 개인 이름과 결합하지 않는다** | 이벤트에 `runId`(익명)만 쓴다. 교육 모드가 이미 sessionStorage + runId 구조라 이 원칙에 맞다 (`CLAUDE.md` 검증 완료 항목) |
| E2 | **개인별 성과 순위·리더보드를 만들지 않는다** | 기능 요청이 와도 거절. "누가 제일 빠른가" 화면은 만들지 않는다 |
| E3 | **소요 시간·질문 횟수를 개인 평가에 쓰지 않는다** | 집계 단위는 개인이 아니라 **항목**이다. "이 항목이 오래 걸린다 → 이 항목 설명이 나쁘다"로 읽는다 |
| E4 | **AI가 사람을 평가하는 기능은 만들지 않는다** | §5.4 고영향 판정을 유지하기 위한 조건이기도 하다 |
| E5 | **점주에게도 이 선을 알린다** | 이용약관·매뉴얼에 "이 기록은 교육 개선용이며 인사평가 용도가 아닙니다" 명시 |
| E6 | **자동화된 결정을 하지 않는다** | 개인정보보호법 제37조의2가 자동화된 결정에 거부권·설명요구권을 부여한다. 애초에 자동 결정을 안 하면 이 의무권 다툼이 생기지 않는다 |

> **E3이 왜 중요한가:** 지표의 해석 방향이 반대다. 신입이 오래 걸리면 그건 **신입의 결함이 아니라 콘텐츠의 결함**이다. 검증하려는 가설이 "체크리스트+영상만 봐도 선배가 붙어있는 시간이 줄어든다"(`CLAUDE.md`)이므로, 측정 대상은 제품이지 사람이 아니다.

## 8. 발표에서 "AI로 개발했다"를 말하는 정확한 표현

### 8.1 문제

`00_진행표.md`가 이미 지적한 그대로다.

> **제품에는 아직 AI 기능이 없다.** AI로 *개발*했을 뿐, 제품이 AI를 *쓰지는* 않는다.

발표에서 "AI로 만들었습니다"라고만 하면 심사위원은 **제품이 AI 서비스**라고 알아들을 가능성이 높다. 그러면 두 가지가 동시에 나빠진다.

| 위험 | 내용 |
|---|---|
| 사실과 다른 인상 | AI 기능을 시연해달라고 하면 보여줄 게 없다. 신뢰가 한 번에 무너진다 |
| 불필요한 규제 질문 | "AI 기본법 대응은 했나요?"라는 질문을 자초한다. 사실 적용 대상이 아닌데도 |

### 8.2 권장 표현 3안

> ⚠️ **아래 인용문의 수치는 2026-09-04 저장소 실측으로 교체된 값이다.** §0.1 A-1이 지적한
> 초판의 오류("4주", "정적 웹앱", "화면 8개", "산출물 12종")는 이 절에서 이미 치환했다.
> **인용문을 다시 고칠 때는 반드시 저장소를 다시 세고 §0.1 A-1도 같이 갱신할 것.**
> 검증 근거: 화면 = `src/app/**/page.tsx` 10개 (`02_화면설계서.md:91-100` S-01~S-10, S-11은 미구현) /
> 산출물 = `00_진행표.md:14-26` 12종 중 파일 존재 10종(7·8번 파일 없음) /
> 기간 = `git log` 최초 `4715fee` 2026-08-31 ~ 최신 2026-09-04, 16커밋.

#### 안 1 — 가장 안전. 개발 방식과 제품을 한 문장에서 분리한다

> "**개발 도구로 생성형 AI를 사용했습니다. 다만 제품 자체는 AI를 호출하지 않습니다** — Next.js 앱이고, 서버에는 이용 기록(`sessionId`·항목 slug)만 파일로 남습니다. 직원 이름·이메일·전화번호는 기기 localStorage에만 있습니다."

- **쓸 곳:** 제품 소개 도입부
- **왜:** "개발 도구로"가 앞에 있어서 오해가 생길 틈이 없다. 뒤에 붙는 사실이 규제 질문도 미리 막는다.
- ⚠️ **"정적 웹앱"·"데이터도 기기 안에"는 삭제했다. 사실과 다르다.** `src/app/api/log/route.ts:15-32`가 요청 본문을 서버의 `data/events.jsonl`에 `fs.appendFile`로 쌓고, `src/app/api/media/route.ts:12-21`이 `fs.readdir`로 서버 파일시스템을 읽는다. 서버 라우트를 가진 Next.js 앱이지 정적 웹앱이 아니다. → §3.6 5번, §5.3(2)
- ⚠️ **`sessionId`를 "익명"이라고 부르지 말 것.** §5.3(2)가 이를 **영구 가명 식별자**로 판정했다(만료·삭제 경로 코드 0건). 되물으면 "이름은 안 붙지만 가명 식별자라서 만료 처리를 배포 전 과제로 잡아뒀습니다"(§0.1 B-2)로 답한다.
- ⚠️ **기간을 말해야 한다면** 저장소로 뒷받침되는 범위까지만 — "저장소 커밋 이력 기준 5일(2026-08-31~09-04, 16커밋)". 그 앞 기획 기간은 저장소에 기록이 없다. **"4주"는 근거가 없어 삭제했다.** 저장소 밖 기획 노트·날짜 기록을 찾으면 그 근거를 여기 붙이고 다시 쓸 것.

#### 안 2 — 개발 속도를 강조할 때

> "**기획부터 구현까지 AI 페어 프로그래밍으로 진행했습니다.** 화면 10개와 산출물 12종 중 10종을 이 방식으로 만들었고, **AI가 만든 결과물은 전부 사람이 검토하고 고쳤습니다.**"

- **쓸 곳:** 개발 역량·속도를 묻는 질문
- **왜:** "페어 프로그래밍"은 도구라는 뜻이 이미 들어 있다. 뒷문장이 저작권상 "인간의 창작적 개입"(§4.4)과 책임성 원칙(§7.B 8번)을 동시에 짚는다.
- ⚠️ **되물으면 상태까지 말할 것.** 산출물 10종 중 **4·5·6번은 초안(검토 필요), 11·12번은 작성 중, 7·8번은 미착수**다(`00_진행표.md:14-26`). "12종 완성"이라고 말하면 사실과 다르다. 화면도 S-11(오류 안내)은 미구현이다(`02_화면설계서.md:100`).

#### 안 3 — 로드맵을 말할 때

> "**현재 버전에 AI 기능은 없습니다.** 촬영 목록 자동 생성을 다음 단계로 계획하고 있고, **그때 필요한 고지·표시 의무는 미리 정리해뒀습니다.**"

- **쓸 곳:** 향후 계획, 또는 AI 관련 질문을 받았을 때
- **왜:** "없다"를 먼저 말해서 오해를 끊고, 준비성을 보여준다. 이 문서(§6)가 그 근거다.
