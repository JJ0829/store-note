
```bash
# 3) 타입 점검 (선택). 오류 0이면 정상
```

각 명령의 뜻:

| 명령 | 뜻 |
|---|---|
| `git clone` | 소스 코드를 내려받는다. 압축파일을 풀어도 결과는 같다 |
| `npm ci` | `package-lock.json`에 적힌 **정확히 그 버전**으로 설치한다. `npm install`은 잠금 파일을 갱신해버리므로 발표 환경 재현에는 `npm ci`가 맞다 |
| `npx tsc --noEmit` | 코드 오류만 검사하고 결과물은 안 만든다. **`.next` 폴더를 건드리지 않아 개발 서버를 죽이지 않는다** |

`node_modules/`는 `.gitignore` 1행으로 제외되므로 clone 후 반드시 `npm ci`가 필요하다.

### ❌ `npm run lint` 는 쓰지 마라

`package.json`에 `lint` 스크립트가 있지만 **실행하면 안 된다.**

1. `next lint`는 Next.js 15.5에서 **deprecated**이고 Next 16에서 삭제된다.
   > ``next lint`` is deprecated and will be removed in Next.js 16.
2. 이 프로젝트에는 **ESLint가 설치돼 있지도 않고 설정 파일도 없다.** 실행하면 대화형 설치 프롬프트에서 멈춘다.

코드 점검은 `npx tsc --noEmit`을 쓴다. (직접 실행해 오류 0으로 통과 확인함.)

### 인터넷 없이도 되나

`npm ci` 한 번만 하면 그 뒤로는 인터넷 없이 빌드·실행된다. 웹폰트를 코드에서 받아오지 않는다 (`next/font` 사용 0건). 글씨체는 `Pretendard → Apple SD Gothic Neo → Malgun Gothic → system-ui` 순으로 시스템에서 찾는다. Pretendard가 번들되어 있지 않으므로 Windows에서는 맑은 고딕으로 표시된다. **깨지지 않고 모양만 다르다.**

`grep -rn "SUPABASE\|ANTHROPIC" src/` → **0건.** Supabase·Anthropic 관련 코드는 저장소에 한 줄도 없다. `.env.example`에서도 이 4개는 주석 처리되어 있다.

`NEXT_PUBLIC_SITE_URL`의 용도는 **카카오톡 공유 미리보기의 `og:url` 하나뿐**이다.

```ts

```

인터넷 주소가 생긴 뒤에 쓰려면 프로젝트 루트에 `.env.local`을 만든다.

```bash
NEXT_PUBLIC_SITE_URL=https://실제주소
```

### ⚠ 이 값은 빌드할 때 HTML에 박힌다

`/p/[slug]`는 `generateStaticParams`를 갖고 `dynamic` 선언이 없어 **빌드 시점에 미리 생성된다.**

**빌드가 끝난 뒤에 `.env.local`을 고쳐도 반영되지 않는다. 다시 빌드해야 한다.**
(개발 모드에서는 요청마다 읽으므로 즉시 반영된다 — 그래서 더 헷갈린다.)

`.env`와 `.env.local`은 `.gitignore` 4-5행으로 제외된다. `.env.example`만 추적된다.

### 6-4. `.next` 손상 — 오류 3종은 전부 같은 병이다

복구법도 하나다:

```bash
# 1) 개발 서버, 에이전트, 워크플로를 전부 종료한다
# 2) .next 폴더를 통째로 지운다

```

**규칙 두 개**
1. **개발 서버를 켜둔 채 `npm run build` 하지 마라.** `.next`가 덮어써져 개발 서버가 죽는다.
2. **워크플로·에이전트가 도는 중에는 빌드하지 마라.** 에이전트가 스스로 `.next`를 지우거나 개발 서버를 띄우기 때문이다.

타입만 확인할 거면 `npx tsc --noEmit`을 쓴다. `.next`를 안 건드린다.

### 6-5. ⚠ 평문 HTTP에서 복사 버튼 4곳 중 3곳이 죽는다 — 아직 안 됩니다

`navigator.clipboard`는 HTTPS 또는 localhost(secure context)에서만 존재한다. 매장 태블릿은 `http://192.168.x.x:3000`(평문 HTTP)으로 접속하므로 **`navigator.clipboard` 속성 자체가 `undefined`다.** "권한 거부"가 아니라 **객체가 없다.** 이 차이가 결과를 갈랐다.

복사 버튼은 4곳인데, **폴백이 실제로 도는 곳은 1곳뿐이다.**

| 위치 | 코드 | 평문 HTTP에서 실제 결과 |
|---|---|---|
| 링크 복사 (`/`, `/p` 등)<br>`CopyLinkButton.tsx:10-17` | `try { await …writeText() } catch { window.prompt() }` | ✅ **폴백 동작.** 팝업이 뜬다 |
| 파일명 복사 (`/shoot`)<br>`ShootBoard.tsx:29-31` | `navigator.clipboard?.writeText(name).catch(…)` | ❌ **완전 무반응.** 오류도 팝업도 없다 |
| 레시피 백업 복사 (`/r`)<br>`RecipeSearch.tsx:49-52` | `navigator.clipboard.writeText(…).catch(…)` | ❌ **무반응.** 팝업 안 뜸 |
| 근무표 카톡용 복사 (`/roster`)<br>`RosterView.tsx:114-117` | 위와 같은 형태 | ❌ **무반응.** 팝업 안 뜸 |

**왜 3곳은 폴백이 안 도는가**

- `ShootBoard`: `?.`(옵셔널 체이닝)은 **뒤에 이어지는 체인 전체를 건너뛴다.** `clipboard`가 `undefined`면 `.writeText(...)`뿐 아니라 `.catch(...)`까지 통째로 생략된다. 그래서 오류조차 안 난다.
- `RecipeSearch` / `RosterView`: `try`도 `?.`도 없다. `undefined.writeText`를 읽는 순간 **동기 TypeError**가 던져진다. `.catch()`는 프로미스가 만들어진 뒤에 붙는 핸들러라 **애초에 붙지도 못한다.**

`document.execCommand("copy")` 같은 구식 폴백도 없다 (`grep -rn "execCommand" src/` → **0건**).

**대처 (코드를 고치기 전까지)**

1. **서버 PC의 브라우저에서 `http://localhost:3000`으로 열면 4곳 다 정상 동작한다.** localhost는 평문이어도 secure context로 쳐준다.
2. 태블릿에서는 화면에 보이는 글자를 **눈으로 옮겨 적는다.** `/shoot`의 파일명은 화면에 그대로 떠 있다.
3. 근무표는 `/roster`의 **"메일로 보내기"** 를 쓴다. 이 버튼은 `mailto:`로 메일 앱을 여는 방식이라 **클립보드와 무관하게 태블릿에서도 동작한다** (`RosterView.tsx:99-108`). 단 직원 이메일이 한 명도 입력돼 있지 않으면 버튼이 비활성화된다.

> 화면 안내문과 어긋나는 곳이 하나 있다. `/roster`는 이메일이 없을 때 "카톡용 복사를 쓰세요"라고 안내하는데(`RosterView.tsx:407`), **그 복사 버튼이 태블릿에서는 안 되는 쪽이다.** 코드 수정 대상으로 남겨둔다.

### 6-7. 포트 3000 고정 — 개발과 실사용의 증상이 다르다

`package.json` 스크립트에 `-p` 옵션이 없다(`"dev": "next dev"`, `"start": "next start"`). 다른 프로그램이 3000을 점유했을 때 **두 명령의 반응이 정반대다.**

| 명령 | 3000이 점유돼 있으면 |
|---|---|
| `npm run dev` (개발) | **3001로 알아서 옮겨간다.** 서버는 뜨지만 태블릿에 저장해 둔 3000 주소가 안 열린다 |
| `npm start` (**매장 실사용**) | **서버가 아예 안 뜬다.** `Failed to start server` + `EADDRINUSE`를 출력하고 즉시 종료된다 |

근거 — `node_modules/next/dist/server/lib/start-server.js:265`:

```js
if (allowRetry && port && isDev && err.code === 'EADDRINUSE' && portRetryCount < 10) {
```

포트 재시도 조건에 **`isDev`가 들어 있다.** 프로덕션(`next start`)은 이 분기를 못 타고 `:270-272`로 떨어져 `process.exit(1)` 한다.

> ⚠ **7장 (다) 매장 PC 경로가 바로 `npm start`다.** 매장에서 "화면이 안 열린다"의 원인이 방화벽이나 Wi-Fi가 아니라 이것일 수 있다. **서버 쪽 검은 창에 `Failed to start server`가 떴는지 먼저 볼 것.**

**대처:** 3000번을 쓰는 프로그램을 찾아서 끈다.

```powershell
netstat -ano | findstr :3000
```

맨 끝에 나오는 숫자가 PID다. 작업 관리자에서 그 PID를 끝내고 `npm start`를 다시 실행한다. (개발 서버를 켜둔 채 `npm start` 한 경우가 가장 흔하다.)

### 6-8. 반드시 프로젝트 루트에서 실행

`src/lib/repo.ts:26`과 API 라우트 2개가 전부 `path.join(process.cwd(), ...)`를 쓴다. 바로가기나 작업 스케줄러로 자동 실행할 때 **"시작 위치"를 프로젝트 폴더로 잡지 않으면 `seed.json`을 못 찾는다.**

`grep -rn "serviceWorker\|manifest.json" src/ public/` → **0건.** 서비스 워커도, 웹 앱 매니페스트도 없다.

## 8장. 매장 태블릿에 띄우기 🅱

**여기는 사장님이 읽는 장이다.**

### 먼저 알아야 할 것 — 아직 안 되는 것이 있다

**아이패드에서 "홈 화면에 추가"를 해도 앱처럼 꽉 찬 화면이 되지 않는다.** 사파리 주소창이 그대로 남는다. 이건 만들다 만 게 아니라 **아직 안 만든 기능**이다.

지금 할 수 있는 방법은 아래와 같다.

### 아이패드

1. 사파리로 주소를 연다.
2. 딴 화면으로 못 넘어가게 잠그려면: **설정 → 손쉬운 사용 → 가이드 접근**을 켠다.
3. 화면을 연 상태에서 **홈 버튼(또는 상단 버튼)을 세 번** 누르면 잠긴다. 직원이 다른 앱으로 나갈 수 없다.

### 안드로이드 태블릿

1. 크롬으로 주소를 연다.
2. 오른쪽 위 점 세 개 → **"홈 화면에 추가"**.
3. 주소창은 남는다. 완전히 꽉 찬 화면이 필요하면 매장용 잠금 앱(Fully Kiosk 등)에 주소를 넣어 쓴다.

### 윈도우 태블릿·PC

- 크롬을 열고 **F11**을 누르면 꽉 찬 화면이 된다.
- 항상 그렇게 열리게 하려면 바탕화면 바로가기를 만들고 대상에 이렇게 넣는다:
  ```
  chrome.exe --kiosk http://192.168.0.10:3000
  ```
  (`192.168.0.10`은 매장 컴퓨터 주소로 바꾼다.)

### 세 기기 모두 반드시 할 것

| 할 일 | 왜 |
|---|---|
| **자동 잠금 끄기** (화면 항상 켜기) | 젖은 손·장갑으로 매번 잠금을 풀 수 없다 |
| **충전기 상시 연결** | 잠금을 꺼두면 배터리가 빨리 준다 |
| **화면 확대(핀치 줌)를 막지 말 것** | 젖은 손으로 볼 때 확대가 필요하다. 일부러 열어둔 것이다 |
| **주소를 북마크에 저장** | 매번 입력할 수 없다 |

### 미리 알아두면 당황하지 않는 것

- **"링크 복사"를 누르면 작은 창이 뜬다.** 고장이 아니다. 그 창에 있는 글자를 직접 긁어서 복사하면 된다. **이건 링크 복사 버튼에만 해당한다.**
- **그 밖의 복사 버튼은 태블릿에서 아무 반응이 없다 — 아직 안 됩니다.** 촬영 목록(`/shoot`)의 파일명 복사, 레시피 목록(`/r`)의 "백업용으로 복사하기", 근무표(`/roster`)의 "복사 (카톡용)" 세 개다. 눌러도 아무 일도 안 일어난다. **고장 맞다. 다만 고치기 전까지는 그렇게 동작한다.**
  - 파일명은 화면에 그대로 떠 있으니 **보고 옮겨 적으면 된다.**
  - 근무표는 옆의 **"메일로 보내기"** 를 쓰면 된다. 이건 태블릿에서도 잘 된다.
  - 꼭 복사해야 하면 **매장 컴퓨터에서 직접** 하면 정상 동작한다.
- **매장 컴퓨터가 꺼지면 태블릿 화면이 안 열린다.** 컴퓨터를 켜 두어야 한다.
- **컴퓨터 주소가 바뀌면 북마크가 안 열린다.** 설치해 준 사람에게 "컴퓨터 주소를 고정해 달라"고 부탁해 둘 것.

## 9장. 백업과 이관 🅰

### 🚨 먼저: 이 저장소에는 원격이 없다

```bash
git remote -v      # → origin  https://github.com/JJ0829/store-note.git
```

**확인했다. 커밋은 이 PC의 `.git` 폴더 안에만 있다.** GitHub에도, 어디에도 사본이 없다.

**그래서 "소스는 git에 있으니 백업 안 해도 된다"가 성립하지 않는다.** 이 PC가 죽으면 `src/`도, 커밋 이력도, 전부 같이 사라진다.

**둘 중 하나를 반드시 할 것.**

**(A) 원격 저장소를 먼저 만든다 (권장)** — 2장 설치보다 **먼저** 해야 아래 절차가 성립한다.

```bash
# GitHub 등에서 빈 비공개 저장소를 만든 뒤
git remote add origin <저장소 주소>
git push -u origin master
```

> ⚠ **반드시 비공개(private)로 만들 것.** `data/seed.json`에 레시피가 들어 있고 **레시피는 매장 영업비밀이다.** 공개 저장소에 올리면 그대로 노출된다.
> `data/events.jsonl`과 `.env.local`은 `.gitignore`로 빠지므로 push에 안 실린다.

**(B) 원격을 안 만들 거면 폴더째 복사한다** — `node_modules/`와 `.next/`만 뺀 **프로젝트 폴더 전체**를 외장하드나 클라우드에 통째로 복사한다. `.git` 폴더를 빼먹지 말 것. 이력이 거기 있다.

### 무엇을 복사하면 되는가

| 대상 | 백업 | 이유 |
|---|---|---|
| **`data/seed.json`** | ✅ **반드시** | 이게 사실상 DB다. 매장·포지션·레시피·프렙이 전부 여기 있다 |
| **`data/events.jsonl`** | ✅ **반드시** | 사용 기록. `.gitignore` 8행으로 git에 안 들어간다. **지우면 끝이다** |
| **`public/media/`** | ✅ **반드시** | 촬영한 사진·영상. 다시 못 찍는다 |
| `.env.local` | ⚠ 있으면 | git에 안 들어간다. 지금은 실질 설정값이 없다 |
| `presentation/매장수첩.html` | ⚠ 발표용 | 손으로 고쳤다면 백업 |
| **`src/`, `package.json`, `.git/` 등 나머지 전부** | ✅ **반드시** (위 (B)를 택했다면) | **원격 저장소가 없다.** 여기 말고 사본이 없다 |
| `node_modules/`, `.next/` | ❌ 복사하지 말 것 | 새 컴퓨터에서 `npm ci` + `npm run build`로 다시 만든다 |

가장 짧게 말하면 **`node_modules/`와 `.next/`를 뺀 프로젝트 폴더 전체**다.

원격 저장소를 만들어 뒀다면(위 (A)) 소스·`data/seed.json`·`public/media/`는 **커밋해서 push한 것에 한해** 지켜진다. `.gitignore`를 확인했다 — 이 셋은 추적 대상이다.

**단, (A)를 택해도 아래 둘은 git이 절대 안 지켜준다.**

- **`data/events.jsonl`** — `.gitignore` 8행으로 제외. **push해도 안 올라간다.** 지우면 끝이다.
- **새로 찍은 사진** — 폴더에 넣기만 하고 `git add` → `commit` → `push`를 안 했다면 그냥 이 PC에만 있다. 사진을 넣은 날은 커밋도 같이 할 것.

### 새 컴퓨터로 옮기기

**원격 저장소를 만들어 둔 경우 (위 A)**

```bash

git clone <저장소 주소> 매장수첩
cd 매장수첩

# 2) 백업해 둔 data/events.jsonl 과 (커밋 안 한) 사진을 덮어쓴 뒤
# 3) 설치하고 빌드한다
npm ci
npm run build
npm start
```

**원격이 없는 경우 (위 B) — 지금 상태가 이쪽이다**

```bash
# 1) 백업해 둔 폴더를 통째로 새 PC에 복사한다 (.git 포함, node_modules·.next 제외)
cd 매장수첩

# 2) 의존성만 새로 깐다
npm ci
npm run build
npm start
```

> `git clone`으로 시작하는 절차는 **원격 저장소를 먼저 만든 뒤에만 성립한다.** 지금은 원격이 없으므로 (B)를 따를 것.

### ⚠ 태블릿 안에 있는 것은 백업할 방법이 없다

체크 기록, 직접 추가한 레시피, 근무표는 **서버가 아니라 태블릿 브라우저 안에** 저장된다.

| 저장 키 | 내용 | 위치 |
|---|---|---|
| `sop:sid` | 기기 구분용 임의 번호 | localStorage |
| `sop:recipes` | 직접 추가한 레시피 | localStorage |
| `sop:roster` | 근무표 | localStorage |
| (교육 모드) | 이번 1회분 진도 | sessionStorage — 창 닫으면 사라진다 |

**브라우저 데이터를 지우거나 태블릿을 바꾸면 이 내용이 전부 사라진다.** 서버로 옮기는 기능은 **아직 안 됩니다.**

**게다가 내보내기 버튼도 태블릿에서는 대부분 안 듣는다** (6-5). 정확한 상황은 이렇다.

| 무엇을 | 버튼 위치 | 태블릿(평문 HTTP) | 서버 PC(`localhost`) |
|---|---|---|---|
| 직접 추가한 레시피 | **`/r`** 맨 아래 "백업용으로 복사하기"<br>(`RecipeSearch.tsx:161-167`) | ❌ 무반응 | ✅ 동작 |
| 근무표 (복사) | `/roster` "복사 (카톡용)" | ❌ 무반응 | ✅ 동작 |
| 근무표 (메일) | `/roster` "메일로 보내기" | ✅ **동작** — 클립보드를 안 쓴다 | ✅ 동작 |

- **레시피 백업 버튼은 `/r`에 있다. `/r/my`가 아니다.** `/r/my`에 있는 버튼은 "이 레시피 삭제" 하나뿐이고, 복사·내보내기 코드는 그 화면에 아예 없다 (`LocalRecipeView.tsx`).
- **직접 추가한 레시피가 0개면 그 버튼은 화면에 보이지도 않는다** (`RecipeSearch.tsx:155` — `mine.length > 0` 조건). 버튼이 안 보인다고 고장이 아니다.

**그래서 현실적인 운영 방법은 이렇다.**

1. **레시피 추가·근무표 편집을 되도록 서버 PC의 브라우저(`http://localhost:3000`)에서 한다.** 거기서는 백업 버튼이 정상 동작한다.
2. 근무표는 태블릿에서 편집했더라도 **"메일로 보내기"로 자기 메일함에 보내두면** 그게 곧 백업이다.
3. **태블릿에서 추가한 레시피는 현재 빼낼 방법이 없다.** 아직 안 됩니다.

> ⚠ **주의: 저장 공간은 주소마다 따로다.** 같은 PC라도 `http://localhost:3000`에서 입력한 것과 `http://192.168.x.x:3000`에서 입력한 것은 **서로 다른 곳에 저장된다.** 태블릿에서 넣은 레시피가 서버 PC의 `localhost` 화면에 나타나지 않는 건 그 때문이다. 백업하려고 PC를 열어봐야 **태블릿 내용은 거기 없다.**

| 태블릿 저장 내용의 서버 백업 | ❌ 없음. 브라우저 데이터 지우면 소실 |

| 평문 HTTP에서의 복사 버튼 3곳 (`/shoot`·`/r`·`/roster`) | ❌ **무반응.** 폴백이 없다. 링크 복사 1곳만 팝업으로 살아난다 (6-5) |
| 태블릿에서 추가한 레시피 빼내기 | ❌ 없음. 백업 버튼이 태블릿에서 안 듣는다 (9장) |
| 원격 저장소(소스 백업) | ❌ **설정돼 있지 않음.** 커밋이 이 PC에만 있다 (9장) |
