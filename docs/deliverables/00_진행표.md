## 이 프로젝트의 특수 사정 (작업 시 계속 고려할 것)

**순서가 뒤집힌 채 시작했다.**
정상 순서는 1~3번(기획·설계)이 코드보다 먼저다. 이 프로젝트는 코드를 먼저 만들었다.
따라서 1~3번은 **설계서가 아니라 역설계 기록**에 가깝다. 그 사실을 문서에 숨기지 않는다.
→ 근거: `docs/08_DECISION_LOG.md` D-001

**개인정보를 실제로 다룬다.**
근무표가 직원의 **이름·이메일·전화번호**를 저장한다 (`src/lib/roster.ts`).
지금은 기기 내 저장이지만 배포 + 서버 연결 시 수집·처리가 된다.
→ 10번(개인정보처리방침)은 선택이 아니라 배포 전 필수다.

**제품에는 아직 AI 기능이 없다.**
AI로 *개발*했을 뿐, 제품이 AI를 *쓰지는* 않는다. 이 구분을 5번에서 분명히 해야 한다.
계획된 "AI 촬영목록 생성"을 붙이는 시점부터 규제 대상이 달라진다.
→ 근거: `CLAUDE.md` "AI의 역할은 텍스트 초안이 아니라 촬영 목록 생성이다"

**2026-09-18 정부지원사업 발표가 걸려 있다.**
심사에서 실제로 볼 가능성이 높은 것은 **4번(라이선스), 10번(개인정보처리방침), 3번(ERD)** 이다.
발표 전에 이 셋은 반드시 끝나 있어야 한다.

**미해결 Blocker가 있고, 문서에서 얼버무리면 안 된다.**
B1 측정 baseline 없음 / B2 배포 시 지표 수집 무동작 / B3 타인 근거 없음(n=1) /
B4 점주가 왜 돈을 내는지 미검증.
→ 근거: `docs/00_PROJECT_CURRENT.md`
