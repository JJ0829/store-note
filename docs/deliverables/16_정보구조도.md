### 1.1 구조의 성격 — 허브 앤 스포크

| 사실 | 근거 | 뜻 |
|---|---|---|
| **최대 깊이 2단** | 홈 → 운영 화면 → 레시피 상세 | 신입이 길을 잃기 어렵다 |
| **홈이 유일한 허브** | 홈에서 14개 경로로 나간다 | 홈만 알면 다 갈 수 있다 |
| **전역 내비게이션이 없다** | `fixed bottom` 탭바 grep 0건 (`RecipeForm` 의 저장 바 하나뿐) | 화면 간 이동은 **뒤로가기 + 홈** 뿐 |
| 뒤로가기는 공통 | `ui.tsx:52` `Screen` 이 `BackButton` 을 내장 | 화면마다 챙기지 않아도 빠지지 않는다 |
| 가로 연결이 몇 개 있다 | `/sales`→`/attendance`·`/contracts`·`/cost`, `/cost`→`/sales`·`/vendors`, `/order`→`/vendors`, `/attendance`→`/contracts`·`/roster` | 데이터가 이어지는 곳끼리 이어놨다 |

### 1.2 고아 화면 없음 — 확인함

전수 확인 결과 **어디서도 못 가는 화면은 없다.**

| 처음에 고아로 보였던 것 | 실제 |
|---|---|
| `/r/my` | ✅ `RecipeSearch.tsx:44` 가 `isLocal(r)` 이면 `/r/my?id=` 로 보낸다. `RecipeForm.tsx:105` 도 저장 후 여기로 |
| `/r/new` | ✅ `/r` 의 `+ 레시피 추가` 버튼 |
| `/backup`·`/shoot`·`/vendors`·`/roster` | ✅ 홈에서 직접 |

> ⚠️ **주의: `href` 문자열만 grep 하면 `/r/my` 가 고아로 잡힌다.** 링크를 헬퍼 함수가
> 만들기 때문이다. 다음에 이 문서를 갱신할 때 같은 착각을 하지 않도록 적어둔다.

## 2. 잠금이 만드는 두 번째 계층

**주소 계층과 접근 계층이 다르다.** 이게 이 제품 IA의 특징이다.

```
공개 (링크만 알면)          🔐 매장 번호 (직원 전부)      🔒 사장님 번호 (사장님만)
├─ /p/{slug} 체크리스트      └─ /r 계열 4개                ├─ /roster
├─ /t/{slug} 교육 모드                                      ├─ /contracts
├─ /prep/{slug} 프렙                                        ├─ /sales
├─ /order 발주                                              ├─ /cost
├─ /shoot 촬영                                              ├─ /vendors
└─ / 홈                                                     ├─ /backup
                                                            └─ /attendance 의 인건비 부분만
```

| 사실 | 근거 |
|---|---|
| 잠금이 **주소 깊이와 무관**하다 | `/r` 은 1단인데 🔐, `/attendance` 는 1단인데 부분 🔒 |
| `/attendance` 는 **화면 안에서 갈린다** | 직원이 직접 찍어야 하므로 화면은 열고 인건비만 `InlineUnlock` |
| 홈은 열려 있지만 **잠긴 화면의 이름은 보인다** | 🔒 배지가 붙은 타일. 존재는 알리고 내용만 가린다 |
| ⚠️ 잠금은 **가림막**이다 | 레시피는 잠긴 상태에서도 페이지 소스에 재료가 있다 (`13` §8) |

## 4. ★ 두 앱의 정보구조가 다르다 — 이 문서의 발견

**같은 제품이라고 말하고 있지만 구조가 다르다.** 시연에서 보여주는 것과 제품 본체가 어긋난다.

### 4.1 대응표

| 기능 | Next 앱 (제품) | 단일 파일 (시연) | 일치 |
|---|---|---|---|
| 홈 | `/` | `#/` | ✅ |
| 프렙 | `/prep/{slug}` | `#/prep` | 🟠 슬러그 없음 |
| 레시피 목록 | `/r` | `#/recipes` | 🟠 **이름 다름** |
| 레시피 상세 | `/r/{slug}` | `#/recipe/{slug}` | 🟠 이름 다름 |
| 교육 모드 | `/t/{slug}` | `#/study` | 🟠 **이름 다름** |
| 체크리스트 | `/p/{slug}` | `#/list` | 🟠 **이름 다름** |
| 근무표 | `/roster` | `#/roster` | ✅ |
| 출퇴근 | `/attendance` | `#/attend` | 🟠 이름 다름 |
| 계약·매출·원가·발주·거래처 | 각 `/xxx` | 각 `#/xxx` | ✅ |
| **운영 묶음** | ❌ **없다** (홈의 `돈` 섹션) | ✅ `#/ops` | ❌ **계층이 다르다** |
| **전역 탭바** | ❌ **없다** | ✅ 6칸 고정 | ❌ **내비게이션 방식이 다르다** |
| 촬영 보드 | ✅ `/shoot` | ❌ **없다** | ❌ |
| 내보내기·되돌리기 | ✅ `/backup` | ❌ **없다** | ❌ |
| 레시피 추가 | ✅ `/r/new` | 🟠 목록 안 폼 | 🟠 |
| 404 화면 | ✅ `not-found` | ❌ 없다 (모르는 해시 → 홈) | 🟠 |

### 4.2 무엇이 문제인가

| # | 어긋남 | 왜 문제인가 |
|---|---|---|
| **1** | **내비게이션 방식이 다르다** — 단일 파일엔 탭바 6칸, Next 앱엔 없다 | 시연에서 "화면 아래 탭으로 옮겨 다닙니다"를 보여주고, 심사위원이 실제 앱을 열면 **그 탭이 없다.** 두 화면의 사용 방식이 다르다 |
| **2** | **계층 깊이가 다르다** — 단일 파일 3단(`#/ops` 경유) vs Next 2단(홈 직행) | 같은 화면을 가는 클릭 수가 다르다 |
| **3** | 라우트 이름이 다르다 — `/t/`↔`#/study`, `/p/`↔`#/list`, `/r`↔`#/recipes` | 문서·발표에서 경로를 인용할 때 어느 쪽인지 매번 확인해야 한다. 실제로 `13`·`14` 를 쓰면서 그랬다 |
| **4** | 단일 파일에 **`/shoot`·`/backup` 이 없다** | 백업은 근로기준법 3년 보존 대응이고 촬영은 핵심 가치 셋 중 하나다. **시연 파일로는 둘 다 못 보여준다** |

### 4.3 어느 쪽이 맞는가 — 판단

**단일 파일의 탭바가 더 낫다.** 근거는 이 프로젝트가 이미 정한 것들과 맞물린다.

| 근거 | 출처 |
|---|---|
| **태블릿이 1순위 기기**다. 태블릿은 화면이 넓어 하단 탭이 자연스럽고, 젖은 손으로 뒤로가기를 반복하기 어렵다 | `CLAUDE.md` 확정 결정 |
| **매일 열리는 화면이 4개**다(프렙·출퇴근·발주·매출). 매번 홈을 거치면 하루에 여러 번 왕복한다 | `CLAUDE.md` |
| 신입은 홈을 안 거치고 링크로 바로 들어온다 — 그때 **다른 화면으로 갈 길이 없다** | §1.1 (전역 내비 없음) |

**그런데 지금 옮기면 안 된다.** 전역 탭바는 레이아웃 변경이고, `14_사용자흐름도.md` 가
정리한 흐름 7개와 `02_화면설계서.md` 가 전부 영향을 받는다. **발표(9/18) 전에 할 일이 아니다.**

→ **결론: 어긋남을 문서로 고정하고, 발표 후에 Next 앱에 탭바를 넣어 맞춘다.**
그 전까지 **발표에서 "탭으로 이동합니다"라고 말하지 않는다** — 단일 파일만의 것이다.

## 5. 이름 규칙 — 지금 있는 것

| 패턴 | 쓰는 곳 | 뜻 |
|---|---|---|
| `/{한 글자}/{slug}` | `/t/` `/p/` `/r/` | **신입에게 카톡으로 보내는 링크.** 짧아야 한다 |
| `/{전체 단어}` | `/attendance` `/contracts` `/vendors` | 사장님이 홈에서 누르는 화면. 짧을 필요가 없다 |
| `/{단어}/{slug}` | `/prep/{slug}` | 목록이 여러 개인 것 |
| `/r/my?id=` | 직접 추가분 | ⚠️ **혼자 다른 규칙.** 빌드 때 주소를 못 만들어서 쿼리로 받는다 (`r/my/page.tsx` 주석) |

⚠️ **`/r/my?id=` 만 쿼리 파라미터를 쓴다.** 서버 DB 로 가면 `/r/{id}` 로 합칠 수 있다.
지금은 시드 레시피만 빌드 시점에 경로가 정해지기 때문이다.
