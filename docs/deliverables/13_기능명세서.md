## 2. F-04 프렙 · 리드타임 — 이 제품의 핵심 기능

> 다른 기능은 종이로 어느 정도 된다. **이건 안 된다** — 수량이 매일 바뀌고, 시각 계산이 들어간다.

### 2.1 동작

| | |
|---|---|
| **입력** | 프렙 목록 slug (URL) · 오늘 날짜 · 현재 시각 · 배수 선택(사용자) |
| **처리** | 항목별로 ⓐ 리드타임 → 사용 가능 시각 ⓑ 발주 → 도착일 ⓒ `recipeSlug` 있으면 배수 환산 |
| **출력** | 항목 목록 · 진행률 · 되돌릴 수 없는 항목의 빨간 테두리 · "지금 걸면 → 내일 07:43부터" |
| **저장** | `localStorage` `prep:{slug}:{날짜}` — **날짜별로 갈린다** (어제 체크가 오늘 안 보인다) |

### 2.2 정책 — 전부 테스트로 고정

| 정책 | 근거 | 고정한 테스트 |
|---|---|---|
| 오늘 안에 끝나면 "오늘", 자정을 넘으면 "내일" | `leadTime.ts:30` `readyAt()` | `readyAt: 30분이라도 자정을 넘으면 '내일'` |
| 24시간 = 내일, 48시간 = 모레 | 같음 | `readyAt: 정확히 24시간은 '내일', 48시간은 '모레'` |
| **3일 이상이면 요일 대신 날짜를 쓴다** | 같음 | `readyAt: 3일 이상이면 요일 대신 날짜를 쓴다` |
| 월말·연말·윤년을 넘어도 맞다 | `daysApart()` | `8/31 → 9/1`, `12/31 → 1/1`, `2/28 → 2/29 (윤년 2028)` |
| **토·일은 배송일로 세지 않는다** | `leadTime.ts:63` `arrivesIn()` | `금요일 발주 +1일은 월요일에 온다` |
| **당일배송(0일)이어도 토요일에는 오지 않는다** | 같음 | `arrivesIn: 당일배송(0일)이어도 토요일에는 오지 않는다` |
| 음수 리드타임이 와도 과거 날짜를 만들지 않는다 | 같음 | `arrivesIn: 음수 리드타임이 들어와도 과거 날짜를 만들지 않는다` |
| 23:59 발주도 날짜가 밀리지 않는다 | 같음 | `arrivesIn: 23:59에 발주해도 날짜 계산이 밀리지 않는다` |
| `recoverable:false` 항목엔 결과 문장이 **반드시** 있다 | `seed.test.ts` | `되돌릴 수 없는 항목에는 결과 문장이 반드시 있다` |
| 주기 라벨은 30일·365일에서 단위가 바뀐다 | `triggerLabel()` | `triggerLabel: 주기는 30일·365일에서 단위가 바뀐다` |

### 2.3 알려진 한계 — 숨기지 않는다

| 한계 | 근거 |
|---|---|
| **365일을 넘으면 전부 "1년마다"로 뭉친다** | 테스트가 이 이름으로 고정 — `알려진 한계: 365일을 넘으면 전부 '1년마다'로 뭉친다` |
| **주기 점검의 마지막 수행일을 저장하지 않는다.** 매일 리셋된다 | `01_MVP기획서.md` §5.6. → "주기가 관리된다"고 말하면 안 된다 |
| ~~리드타임+배수가 2건에만 붙는다~~ → ✅ **2026-09-10 에 8건.** 바 부재료에 전부 레시피가 붙었고 **만드는 순서까지** 프렙 안에 들어왔다 | (숫자 정본: [21_화면명세.md §1-b](21_화면명세.md)) |
| "지금 걸면" 시각이 화면을 열어둔 채로는 갱신되지 않는다 | `01` §5.7 |

## 8. 공통 — 잠금 두 종류

> **★ 두 개는 다른 물건이다. 헷갈리면 제품이 망가진다.**

| | 아는 사람 | 가리는 것 | 막을 상대 | 화면 |
|---|---|---|---|---|
| **사장님 PIN** | 사장님만 | 매출·원가·거래처·계약서·인건비·근무표·백업 | 같은 매장 **직원** | 7곳 🔒 |
| **매장 PIN** | **직원 전부** | 레시피 | **매장 밖 사람** | `/r` 계열 🔐 |

| 정책 | 근거 | 테스트 |
|---|---|---|
| PIN을 평문으로 저장하지 않는다 (FNV-1a 단방향) | `pinDigest.ts:18` | `PIN을 그대로 저장하지 않는다` |
| **★ 소금이 달라 같은 번호도 저장값이 다르다** | 같음 | `★ 같은 번호라도 사장님 것과 매장 것의 저장값이 다르다` |
| **★ 매장 번호로 사장님 화면이 열리지 않는다** | `storeGate.ts` | `★ 매장 번호로는 사장님 화면이 열리지 않는다` |
| **★ 사장님 잠금이 풀리면 레시피도 열린다** (번호 두 개 안 외우게) ⚠️ **`STORE_PIN` 이 없을 때만** — 있으면 서버가 쿠키만 본다 | `storeGate.isUnlocked()` (브라우저 폴백 전용) | `★ 사장님 잠금이 풀려 있으면 레시피도 열린다` |
| 4자리 미만은 만들지 않는다 | 양쪽 `setPin()` | `4자리 미만은 만들지 않는다` |
| **PIN을 안 만들었으면 잠그지 않는다** (첫 사용자를 가두지 않는다) | `needsPin()` | `PIN을 안 만들었으면 잠그지 않는다` |
| 만들면 곧바로 열린 상태가 된다 | `setPin()` | `만들면 곧바로 열린 상태가 된다` |
| 해제 상태는 `sessionStorage` — 브라우저 닫으면 재잠금 | 양쪽 `unlock()` | `잠금 해제는 sessionStorage에 둔다` |

> ### ⚠️⚠️ 이 잠금의 성격 — 과장하면 거짓이 된다
>
> **두 겹의 성격이 갈렸다. 뭉뚱그리면 절반이 거짓이 된다.**
>
> ✅ **매장 PIN(레시피)은 서버가 막는다** — `ServerStoreGate`·`fb1389a`·2026-09-10.
> 쿠키가 없으면 `children` 을 아예 안 그리므로 **페이지 소스에도 없다.** 여기 적혀
> 있던 `curl .../r/shokupan | grep 강력분` → 나온다 는 **이제 안 나온다**
> (`tests/builtPages.test.ts` 가 결과와 원인을 둘 다 못 박는다).
> ⚠️ **단 `STORE_PIN` 환경변수를 넣었을 때만이다.** 안 넣으면 막지 않고 빨간 띠로 알린다.
>
> ⛔ **사장님 PIN(돈·사람)은 여전히 가리개다.** 검사가 브라우저 안에서 돌고
> 데이터도 `localStorage` 에 그대로 있다. 막아지는 것은 "브라우저로 열었을 때
> 화면에 안 보이는 것"까지다. **진짜 차단은 서버(Supabase RLS)** 이고 그건 아직이다.
> → `06_보안설계.md` V-19·V-20

## 10. 이 명세서가 드러낸 구멍

기능을 표로 정리하면서 나온 것들이다. **기능 자체의 결함이 아니라 명세의 빈칸이다.**

| # | 무엇 | 왜 문제인가 |
|---|---|---|
| 1 | **F-02 교육 모드 · F-03 체크리스트에 테스트가 0건** | 이 둘이 원래 제품의 출발점인데, 정책을 고정한 테스트가 없다. `critical` 확인 게이트는 브라우저로만 확인됐다 |
| 2 | **체크리스트에 체크 이벤트가 없다** | `PrepView`는 `prep_check`를 남기는데 `/p/[slug]`는 아무것도 안 남긴다 → 완주율·`critical` 누락을 셀 수 없다 (`01` §8.4 #5) |
| 3 | **되돌리기 "덮어쓴다"가 테스트로 안 박혀 있다** | 3년 보존 대상을 지우는 동작인데 화면 확인에만 의존한다 |
| 4 | **`localRecipes` 의 `my-` 접두사 규약이 테스트 없음** | 시드 레시피와 섞이면 조회가 깨진다 |
| 5 | **입력 검증 정책이 화면마다 흩어져 있다** | 시급 0 = "미입력", `packAmount` 0 = "계산 안 함" 같은 규칙이 lib마다 따로 산다. 한 곳에 모은 표가 없다 |

→ 1·3·4는 테스트를 더하면 닫힌다. 2는 코드 변경. 5는 이 문서 §11로 다음에 정리한다.
