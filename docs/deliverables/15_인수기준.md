| 층 | 무엇을 판정하나 | 지금 상태 |

## 3. ② 화면 인수 시나리오 (Given / When / Then)

## 5. ⛔ 비어 있는 칸 — 내가 정할 수 없는 것

### 5.1 실증 성공 판정 임계값

측정 설계는 있다(D-003). **숫자가 없다.**

| 항목 | 설계 | 임계값 |
|---|---|---|
| 대상 | 실제 주방 1곳, 신입 3~5명 | 🔬 계획 |
| Day 1~2 | 체크리스트 **없이** 근무. **선배가** 질문 횟수를 센다 = baseline | 🔬 |
| Day 3~4 | 링크 전달 후 같은 방식 | 🔬 |
| 1차 지표 | 질문 횟수의 변화 | 🔬 |
| **판정** | **몇 % 감소를 성공으로 볼 것인가** | ⛔ **미정** |

> **이 칸이 비어 있으면 데이터가 나와도 "성공"을 선언할 수 없다.**
> 발표 전에 정하는 편이 안전하다 — 심사에서 "성공 기준이 뭡니까"를 물으면
> 지금은 답이 없다.

### 5.2 PIN 분실 정책

사장님이 번호를 잊으면 매출·계약서에 **영구히** 못 들어간다. 서버가 없어 재설정 메일도 불가.

| 선택지 | 대가 |
|---|---|
| ⓐ 복구를 두지 않는다 (현재) | 데이터가 사실상 잠긴다. 백업 JSON 이 유일한 우회 |
| ⓑ 백업 JSON 으로 우회 안내 | 문구만 추가. 백업을 안 해뒀으면 무용 |
| ⓒ 잠금 초기화 버튼 (데이터는 유지) | 잠금의 의미가 약해진다 — 누구나 초기화 가능 |

→ **ⓑ가 비용 대비 합리적으로 보이지만, 잠금 강도를 낮추는 결정이라 사장님 판단이다.**

### 5.3 이용 기록 보유기간

`/api/log` 가 **무기한 append** 한다. 개인정보처리방침에 숫자가 필요하다. ⛔ 미정.
