# 0장. 지금 이 서비스의 실제 상태

**방침을 정확하게 쓰려면 이걸 먼저 확정해야 한다.** 흔한 처리방침 템플릿을 그대로 붙이면
없는 항목을 쓰게 되고, **과다 기재도 그 자체로 위반이다.**

## 0-1. 구조

| 사실 | 근거 |
|---|---|
| **서버 데이터베이스가 없다.** 매장 콘텐츠는 저장소 안의 정적 파일이다 | `data/seed.json` · `src/lib/repo.ts` |
| **회원가입·로그인이 없다.** 사용자 계정 개념 자체가 없다 | 인증 라우트 0건, `src/app/` 전수 확인 |
| **동의 화면·동의 체크박스가 없다** | 코드 0건. → "이용자 동의를 받아 수집한다"고 쓰면 거짓이다 |
| **이용자 데이터는 브라우저 저장소에만 있다.** 서버로 보내지 않는다 | `localStorage` 4키 + `sessionStorage` 1키. 3장 표 |
| 서버로 가는 유일한 경로는 **`/api/log`** (익명·가명 이용 기록) | `src/app/api/log/route.ts` |
| `/api/media`는 `public/media/` **파일명 목록만** 돌려준다. 개인정보 없음 | `src/app/api/media/route.ts:12-21` |
| 서버는 **IP·User-Agent·Referer·쿠키를 기록하지 않는다** | `src/app/api/log/route.ts:18` — `request`는 `.json()`에만 쓰인다. 미들웨어 없음 |
| 메일은 **`mailto:`로 이용자의 메일 앱을 열 뿐이다.** 서비스가 대신 보내지 않는다 | `src/components/RosterView.tsx:105-107` |
| **사진·영상 업로드 기능이 없다** | `src/` 전체에 `<input type="file">` 0건. `ShootBoard.tsx`는 파일명 복사만 한다 |

→ **따라서 현행 구조에서 서비스가 "개인정보처리자"로서 수집·보관하는 범위는 매우 좁다.**
이 방침에서 가장 정직하고 강력한 문장은 **"우리는 거의 아무것도 수집하지 않는다"**이며, 실제로 코드가 그렇다.

## 0-2. 그러나 — 직원 개인정보를 다루는 기능이 있다

**이 점을 흐리면 안 된다.**

근무표 기능(`src/lib/roster.ts`)은 직원의 **섹션·이름·이메일·전화번호**와 **날짜별 근무 배정**을 다룬다.

```ts
// src/lib/roster.ts:11-19
export type Staff = {
  id: string;
  section: string;   // 제빵 / 바 / 홀 / 주방
  name: string;
  email: string;
  phone: string;
};
```

- 저장 위치: `localStorage` 키 `sop:roster` (`src/lib/roster.ts:29`)
- **서버로 전송되지 않는다.** `loadRoster()`를 호출하는 파일은 `RosterView.tsx` 하나뿐이고,
  `RosterView.tsx`에는 `/api/log` 호출이 없다.
- **입력하는 사람과 정보주체가 다르다.** 직원이 자기 정보를 넣는 화면이 없고 **운영자(점주)가 대신 입력**한다
  (`src/components/RosterView.tsx:60-78`).
- 이름만 필수다. `if (!name.trim()) return;` (`RosterView.tsx:61`). 섹션·이메일·전화번호는 비어도 저장된다.
  `<input>`에 `required` 속성이 없다.

**법적 귀속 정리 (중요):**

| 데이터 | 개인정보처리자 | 방침에서의 위치 |
|---|---|---|
| 직원 이름·이메일·전화번호·근무배정 | **매장(점주) 본인** | 서비스의 "수집 항목"이 **아니다**. 서비스가 전송받지 않는다 |
| `/api/log` 이용 기록 | 서비스 운영자 | 서비스의 수집 항목 (1장) |

직원 개인정보에 대한 법적 의무(열람·정정·삭제 응대, 안전조치)는 **점주가 진다.**
서비스는 그 데이터를 다루는 **도구**를 제공할 뿐이다. **이 구분을 문서에서 흐리면 안 된다.**
다만 도구가 만들어내는 위험(4장의 메일 평문 문제)은 도구 제작자의 책임 범위에 들어온다.

## 0-3. 어느 버전을 말하는 방침인가 — 두 버전의 수집 프로필이 정반대다

| | Next.js 앱 (`src/`) | 단일 파일 버전 (`presentation/프렙노트.html`) |
|---|---|---|
| 배포 상태 | **로컬 `npm run dev`만. Vercel 미배포** | **Claude Artifact로 시연용 1회 게시 = 현재 외부 접근 가능한 유일한 버전** |
| 서버 전송 | `/api/log` 있음 | **없다.** `fetch`/`sendBeacon` 0건 (grep 확인) |
| 가명 식별자 `sop:sid` | 있음 | **없다.** `sessionId` 0건 |
| 외부 요청 | **0건.** 폰트는 기기 스택만 (`src/app/globals.css:3-6`) | **Google Fonts 로드** → 열람자 IP가 미국으로 (`프렙노트.html:11-13`) |
| 저장 키 이름 | `sop:roster` 등 | **다르다** — `roster`, `roster:mode`, `recipes:mine`, `prep:…`, `list:…` |

즉 **서버 수집이 있는 버전은 외부에 없고, 외부에 있는 버전은 서버 수집이 없는 대신 IP가 국외로 나간다.**
방침 본문에 **적용 범위(어느 버전·어느 배포 환경)를 반드시 명시**해야 한다. → 부록 D 빈칸 [B-1]

> ⚠️ 추가 사실: 정식 배포(Vercel)에서는 `/api/log`의 파일 쓰기가 막혀 **조용히 실패한다**
> (`src/app/api/log/route.ts:28-30` 빈 catch). "수집한다"고 써 놓고 실제로는 아무것도 쌓이지 않는 상태가 될 수 있다.

## 0-4. 서버 연결(Supabase) 시점부터 무엇이 달라지는가

| 항목 | 현재 | Supabase 연결 후 |
|---|---|---|
| 직원 개인정보 저장 위치 | 이용자 기기(브라우저)만 | **서비스 서버(수탁자 인프라)** |
| 서비스의 수집 항목 | 이용 기록만 | **직원 이름·이메일·전화번호·근무배정 전부 추가** |
| 처리 위탁 (법 제26조) | 없음 → 기재 금지 | **발생. 수탁자·위탁업무 내용 공개 의무** |
| 국외 이전 (법 제28조의8) | 없음 → 기재 금지 | **발생 가능. 제2항 각 호 + 이전 근거 기재 의무** |
| 열람·정정·삭제 응대 | 이용자가 자기 기기에서 직접 | **서비스가 응대 절차를 갖춰야 함** |
| 안전성 확보 조치 | 기기 보안에 의존 | **접근통제·암호화·접속기록 등 실질 조치 필요** |
| 개인정보 유출 통지·신고 | 사실상 해당 없음 | **해당됨** |
| 파기 | 브라우저 데이터 삭제 | **파기 절차·방법 문서화 + 실제 삭제 구현** |

→ **연결 시점에 이 방침은 전면 개정 대상이다.** 상세 기재사항은 **부록 B**.

# 1장. 수집하는 개인정보 항목

**아래 표는 코드에서 확인한 것과 정확히 일치한다. 여기에 없는 항목은 이 방침에 쓰면 안 된다.**

## 1-1. 서비스가 서버로 수집·보관하는 항목

수집 경로는 `/api/log` 하나뿐이다 (`src/app/api/log/route.ts`).

| 항목 | 수집 시점 | 저장 위치 | 필수·선택 | 보관 기간 | 파기 시점 |
|---|---|---|---|---|---|
| **기기 식별값** `sessionId` (난수) | 체크리스트·프렙·레시피 화면을 열거나 조작할 때 | 서버 `data/events.jsonl` | 필수 (거부 수단은 5장) | **[ ] 미정 ⚠️** | **[ ] 파기 코드 없음 ⚠️** |
| **이용 기록** — 화면 종류(`positionSlug`/`prepSlug`/`recipeSlug`), 항목 id(`taskId`), 배수(`scale`), 회차 id(`runId`), 항목 수(`totalTasks`), 소요 시간(`durationSec`), 확인 수(`confirmedCount`), 되돌릴 수 있는 항목인지(`recoverable`), 모드(`mode`) | 위와 같음 | 서버 `data/events.jsonl` | 필수 | **[ ] 미정 ⚠️** | **[ ] 파기 코드 없음 ⚠️** |
| **설문 응답** `askedSenior` — "선배에게 몇 번 물어봤나" 4개 선택지 중 하나 | 이용자가 설문 버튼을 누를 때 | 서버 `data/events.jsonl` | **선택** (안 누르면 전송 없음) | **[ ] 미정 ⚠️** | **[ ] 파기 코드 없음 ⚠️** |
| **수집 시각** `at` (ISO 8601) | 서버가 기록할 때 자동 부여 | 서버 `data/events.jsonl` | 필수 | **[ ] 미정 ⚠️** | **[ ] 파기 코드 없음 ⚠️** |

전송 지점 11곳 전부 확인: `ChecklistView.tsx:77,267` · `PrepView.tsx:158,168,188` ·
`RecipeDetail.tsx:54,90` · `TrainingMode.tsx:101,117,132,219`.
이벤트 이름 10종 (`view`, `survey`, `prep_view`, `prep_check`, `prep_scale`, `recipe_view`,
`recipe_scale`, `training_start`, `critical_confirm`, `training_complete`) —
`data/events.jsonl` 58줄의 실제 필드와 교차 확인했고 위 표 외의 필드는 0건이었다.

**`sessionId`에 대해 정직하게 적어야 하는 것:**

- 생성식: `Math.random().toString(36).slice(2) + Date.now().toString(36)`
  (`ChecklistView.tsx:20-31`, `PrepView.tsx:26-38`, `RecipeDetail.tsx:17-29`)
- `localStorage` 키 `sop:sid`에 저장되어 **영구 재사용된다. 만료·삭제 경로가 코드에 없다.**
- 이름·이메일과 연결하는 코드는 **없다** (grep 확인: `/api/log` payload 11곳에 `name`/`email`/`phone` 0건).
- **그러나 "완전 익명"이라고 단정하지 말 것.** 체크리스트 링크가 개인 휴대폰으로 공유되면
  `sop:sid`는 사실상 **1인 1:1로 고정된 영구 가명 식별자**가 된다.
  → 방침 문구는 **"익명"이 아니라 "가명 처리된 이용 기록"**으로 쓰는 것이 안전하다.
- **교육 모드(태블릿, `/t/…`) 4개 이벤트는 `sessionId`를 보내지 않는다** (`TrainingMode.tsx:30-39`).
  11개 전송 지점 중 7곳에만 붙는다. 화면별로 구분해 쓸 근거가 된다.

> ⚠️ **코드가 이 표를 보장하지 않는다.** `src/app/api/log/route.ts:23`은 받은 JSON을
> `{ ...body, at }`으로 그대로 저장한다. 스키마 검증·화이트리스트가 없어 **누구든 임의 JSON을 POST할 수 있다.**
> 방침에 항목을 열거하려면 **서버측 화이트리스트를 넣는 것이 안전하다.** → 부록 A #6

## 1-2. 이용자 기기에만 저장되며 서비스가 전송받지 않는 항목

**이건 "수집 항목"이 아니다.** 서비스는 이 데이터를 받지 않는다. 다만 **정보주체가 알아야 하는 사실**이라 명시한다.

| 항목 | 입력 시점 | 저장 위치 | 필수·선택 | 서버 전송 |
|---|---|---|---|---|
| 직원 **이름** | 점주가 근무표 화면에서 직접 입력 | 기기 `localStorage` `sop:roster` | **필수** (`RosterView.tsx:61`) | **없음** |
| 직원 **이메일** | 위와 같음 | 위와 같음 | **선택** (비면 메일 발송 대상 제외, `RosterView.tsx:97`) | **없음** |
| 직원 **전화번호** | 위와 같음 | 위와 같음 | **선택** | **없음** |
| 직원 **섹션** (제빵/바/홀/주방) | 위와 같음 | 위와 같음 | 선택 (비면 "미지정") | **없음** |
| **근무 배정** (직원 × 날짜 → 조 이름) | 점주가 표에서 선택 | 위와 같음 | 선택 | **없음** |

**이것이 이 서비스에서 개인정보가 실제로 외부로 나가는 유일한 경로다.**
서비스가 보내는 것이 아니라 **이용자가 직접 보내지만, 그 본문을 만드는 것은 우리 코드다.**

### 무슨 일이 일어나는가

`src/lib/roster.ts:141-148` — `buildEmailBody()`가 `data.staff` **전체를 필터 없이** 돌며

// src/lib/roster.ts:141-148
for (const s of data.staff) {

    pad(s.section || "-", 8) +
      pad(s.name, 12) +
      pad(s.email || "-", 26) +

### 왜 문제인가

**`bcc`는 수신자 헤더만 가린다. 본문은 모든 수신자가 그대로 본다.**

→ 근무표 메일을 받은 직원 **1명이 나머지 전 직원의 이메일과 전화번호를 전부 얻는다.**
→ **bcc의 보호 효과가 실질적으로 무효다.**
→ 점주는 이 동작을 모를 수 있다. 화면이 "숨은참조로 보호된다"고 말하고 있기 때문이다.

| `RosterView.tsx:383-384` | "받는 사람은 숨은참조로 넣어서 직원끼리 서로 주소가 보이지 않습니다" | **사실과 다름** |

| 5 | 복사 기능은 **연락처를 뺀 근무표만** 복사하도록 분리한다 | 단톡방 확산 경로 차단 |
| 6 | 발송 전 **"이 메일에는 직원 N명의 이메일·전화번호가 포함됩니다"** 확인 창을 띄운다 | 최소한 점주가 알고 보내게 된다 |

**방침에 반드시 들어가야 하는 고지 (개선 전 기준):**

> **근무표 메일·복사 기능 안내**
> 근무표를 메일로 보내거나 복사하면, 그 본문에 **등록된 전 직원의 섹션·이름·이메일·전화번호가 그대로 포함됩니다.**
> 받는 사람을 숨은참조로 넣더라도 **본문의 연락처는 수신자 전원이 볼 수 있습니다.**
> 서비스는 이 메일을 대신 보내지 않으며, 발송 여부와 수신자는 이용자가 직접 결정합니다.
> 발송으로 인한 개인정보 제공의 책임은 발송한 이용자(매장)에게 있습니다.
> **직원의 연락처를 다른 직원에게 알릴 필요가 없다면, 발송 전에 본문에서 해당 부분을 지우십시오.**

## 4-3. 외부 CDN (Google Fonts) — IP가 제3자에게 전달되는 구조

| 버전 | 외부 요청 | 근거 |
|---|---|---|
| Next.js 앱 (`src/`) | **없음.** `next/font` 미사용, `globals.css`에 외부 `@import` 없음, 폰트는 기기 스택만 | `src/app/globals.css:3-6`, `src/app/layout.tsx` |
| **`presentation/프렙노트.html`** | **있음** | `:11-13` |
| `presentation/app.html` | 있음 | `:2-4` |
| `public/app.html` | 있음 | `:11-13` |

```html
<!-- presentation/프렙노트.html:11-13 -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=IBM+Plex+Mono...">
```

이 `<link>` 때문에 **열람자의 브라우저가 Google(미국) 서버에 직접 요청을 보낸다.**
그 과정에서 **IP 주소·User-Agent·Referer가 Google LLC에 전달된다.**

- 이 파일들은 `fetch`/`sendBeacon` 호출이 **0건**이지만(grep 확인),
  "서버 없이 완전히 로컬로 동작한다"는 서술은 **이 부분에서 부정확하다.**
- **이 파일이 Artifact 게시본이므로, 현재 외부에서 접근 가능한 유일한 버전에 이 전송이 있다.**

❓ **이것을 개인정보처리자의 "국외 이전"으로 볼지, 이용자 브라우저의 직접 요청으로 볼지는 해석이 갈리는 영역이다.**
법률 검토가 필요하다.

**가장 깨끗한 해법: 폰트를 파일에 내장하거나 기기 폰트 스택으로 바꿔 외부 요청을 없앤다.**
`<link>` 3줄을 지우는 문제이고, 그러면 **국외 이전 논점 자체가 사라진다.** → 부록 A #7

개선 전까지 방침에 넣을 고지:
> 이 페이지는 화면 글꼴을 불러오기 위해 Google LLC가 운영하는 `fonts.googleapis.com` ·
> `fonts.gstatic.com`에 접속합니다. 이 과정에서 이용자의 IP 주소와 브라우저 정보가
> Google LLC(미국)에 전달될 수 있습니다. 서비스는 이 정보를 받지 않으며 별도로 보관하지 않습니다.

# 6장. 개인정보 보호책임자

## 6-1. 지정 의무 여부 — 결론: 지정은 면제되나 **기재는 면제되지 않는다**

| 단계 | 내용 | 근거 |

| 예외 | 시행령이 정하는 기준에 해당하는 자는 지정하지 않을 수 있다 | 제31조 제1항 단서 |

지정하지 않아도 **대표자가 자동으로 보호책임자가 되므로, 대표자 성명과 연락처를 반드시 적어야 한다.**

- 소상공인 = 「중소기업기본법」상 소기업 중 상시 근로자 10명 미만이고, 업종별로
  광업·제조업·건설업·운수업 10명 미만, **그 외 업종 5명 미만.**
- ❓ **시행령 제32조 제1항에 "다만 ~ 제외한다" 형태의 단서가 있는지 원문 확인이 안 됐다.**
  요약 자료들이 서로 다르게 옮기고 있어 law.go.kr 원문 확인이 필요하다.
- ❓ 연간 매출액 일정 규모 이상은 시행령 제32조 제4항에 따라 자격요건을 갖춘 사람을 지정해야 한다 —
  현 단계에서는 무관하다.

## 6-3. 사업자등록 전이어도 의무가 있다

# 부록 B. 서버 연결(Supabase) 시 추가로 필요한 기재사항

**Supabase를 붙이는 순간 이 방침은 전면 개정 대상이다.** 직원 개인정보가
"기기에만 있는 것"에서 **"서비스가 수집·보관하는 것"**으로 바뀐다.

## B-1. 1장 수집 항목 표에 추가되는 것

| 항목 | 성격 |
|---|---|
| 직원 이름 | **필수** — 서버 수집으로 전환 |
| 직원 이메일 | 선택 |
| 직원 전화번호 | 선택 (부록 A #4에서 삭제하면 해당 없음) |
| 직원 섹션 | 선택 |
| 근무 배정 (직원 × 날짜) | 선택 |
| 매장 식별 정보 / 로그인 계정 | **인증을 붙이면 신규 발생** |
| 접속 기록 · IP · 접속 기기 정보 | **서버·수탁자가 자동 기록** → 법 제30조 제1항 제7호 대응 필요 |

## B-2. 새로 발생하는 필수 기재사항

| 근거 | 추가할 내용 |
|---|---|
| **법 제26조 제2항** (처리 위탁 공개) | **수탁자 / 위탁 업무 내용** 표. 최소 2열 (예: Supabase Inc. — 데이터 보관·처리 / Vercel Inc. — 서비스 호스팅). 관행상 보유·이용 기간도 함께 적는다 |

| **시행령 제31조 제1항 제2호** | 위 제2항 각 호를 **처리방침 필수 기재사항으로 끌어온다** |
| **시행령 제31조 제1항 제3호** | **안전성 확보 조치**에 관한 사항 (접근권한 관리, 접근통제, 암호화, 접속기록 보관·점검, 악성프로그램 방지 등) |

| 법 제30조 제1항 제7호 | 접속기록 등 자동 수집 장치의 설치·운영 및 **거부 방법** |
| 법 제34조 | **개인정보 유출 통지·신고** 절차 — 서버 보관 시 실질적으로 해당된다 |

> ⚠️ **위탁과 국외 이전은 별개다. 각각 써야 한다.**
> Supabase·Vercel은 해외 사업자이므로 **①제26조 위탁 공개 + ②제28조의8 국외 이전 사항** 둘 다 들어간다.
> 하나만 쓰면 누락이다.
>
> 💡 **리전을 서울(icn1)로 고정하면 국외 이전 논점을 줄일 수 있다.**
> ❓ 다만 Vercel 무료 플랜에서 리전 고정과 함수 실행·로그 저장 위치가 실제로 국내로 한정되는지는 별도 확인 필요.
