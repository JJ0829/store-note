## 1. 창업 아이템 개요 — **20점**

> ※ 처음 접하는 평가위원이 이해할 수 있도록, 무엇을 · 누구에게 · 어떻게 제공하는 서비스인지 순서로 작성

| | |
|---|---|
| **아이템명** | **매장수첩** — 개인 카페·베이커리 매장 운영 도구 |
| **한 줄 소개** | 사람 머릿속에만 있던 매장의 기준을, 매일 아침 태블릿에서 열리는 **하나의 화면**으로 바꾸는 서비스입니다. |

**해결하려는 문제** *(3줄 이내)*

> 개인 카페·베이커리는 **모든 기준이 특정 개인의 머릿속에 있습니다.** 프렙 양은 아침 담당자만, 발주 수량은 사장만 알아서 그 사람이 쉬면 매장이 흔들립니다.
> 저는 **호스피탈리티 16년, 베이커리·브런치 카페·레스토랑에서 셰프·주방장으로 신입을 가르치는 쪽**에 있었고, **다섯 곳의 오픈 멤버**로 백지에서 기준을 세워봤습니다.
> 이 업계는 이직률이 높아, 기준을 사람이 들고 나가면 매장이 그때마다 처음부터 다시 시작합니다.

**목표 고객** *(1문장)*

> **직원 2~10명 규모의 개인 카페·베이커리 점주**가, 신입이 들어왔을 때와 매일 아침 프렙·발주를 시작할 때 씁니다. (본사가 사진 매뉴얼을 내려주는 프랜차이즈는 대상이 아닙니다.)

**창업 동기 및 사업 목적** *(3줄 이내)*

> 16년간 매번 같은 것을 다시 가르쳤습니다. 문제는 매뉴얼이 없어서가 아니라, **매뉴얼이 글이어서 사람마다 다르게 읽히기** 때문이었습니다.
> 그래서 만들 것은 더 좋은 문서가 아니라 **가장 잘하는 사람의 시연을 박제한 것**이라고 판단했습니다.
> 개인 매장이 사람에 기대지 않고도 같은 품질을 내게 하는 것이 목적입니다.

> ### ◤ 자체 채점 — **A (18~20 / 20)**
> **강함**: 「해결하려는 문제」 칸이 *"본인의 경험·관찰을 근거로"* 를 요구하는데, **16년 · 셰프/주방장 · 오픈 멤버 5곳**이 그 칸에 정확히 들어맞습니다. 이 계획서에서 가장 방어가 쉬운 항목입니다.
> **위험**: 「목표 고객」의 *직원 2~10명* 은 **제가 추정한 숫자**입니다. → ⛔ **사장님 확인** (근거 없으면 규모 표현을 빼고 *"개인 카페·베이커리 점주"* 로만 두는 편이 안전합니다)

## 2. MVP 개발 현황 및 구현 기능 — **15점**

> ※ 교육 중 제작한 MVP의 실제 화면과 동작하는 기능을 근거로 / 어떤 AI 코딩 도구로 무엇을 어디까지 구현했는지

**개발 규모** 화면 **19개** · 자동화 테스트 **○○○건**(⛔ `npm test` 로 확정) · 타입 오류 **0** · 프로덕션 빌드 통과 · **런타임 의존성 3개**(`next`·`react`·`react-dom`)

| 구현 기능 | 활용 AI 도구 | 주요 내용 | 완성도 |
|---|---|---|---|
| **프렙 리드타임 관리** ★핵심 | Claude Code (바이브코딩) | 오늘 안 하면 **내일 아침에 터지는** 항목을 계산해 경고. 콜드브루 12~24h · 반죽 12~18h · 르방 매일 · 생지 해동 12h | ■ 완료 |
| **레시피 · 배수 계산** | Claude Code | 「1배합=식빵 6개」에서 9개가 필요하면 1.5배. **g↔ml 환산은 밀도를 모르므로 의도적으로 차단** | ■ 완료 |
| **매장 운영 7종** | Claude Code | 원가 · 근태 · 출퇴근 · 매출 · 발주 · 거래처 · 근로계약서. **따로 만들지 않고 기존 데이터에 연결**해 「오늘 남은 돈」까지 한 줄로 이어짐 | ■ 완료 |
| **AI 촬영 목록 생성** | **Claude API** (`POST /api/shoot-plan`) | 포지션명을 넣으면 *"이 18개를 찍으세요"* 목록 생성. **SDK 없이 REST 호출**로 의존성 유지 | ■ 완료 |
| **클라우드 이관 · 서버 인증** | Claude Code | 현재 브라우저 저장 → Supabase 이관, 서버 기반 접근 통제 | □ 진행중 |

**기술적으로 판단한 것 세 가지** *(평가항목: 기술의 차별성)*

1. **AI 에게 레시피 본문을 쓰게 하지 않았습니다.** 이 서비스가 푸는 문제가 *"기준이 사람 머릿속에 있다"* 인데, AI 가 기준을 지어내면 **기준을 AI 머릿속으로 옮기는 것**일 뿐입니다. 그래서 AI 는 *무엇을 찍을지* 만 제안하고 **결과를 저장하지 않습니다.**
2. **매장의 하루는 자정이 아니라 새벽 4시에 바뀝니다.** 마감조가 01시에 퇴근하는 날 23:50 의 체크가 00:10 에 사라지면 안 되기 때문에, 날짜 경계를 별도로 구현했습니다.
3. **모르는 값을 0 으로 세지 않습니다.** 단가를 못 구한 재료를 0원으로 처리하면 원가율이 실제보다 낮게 나오고, 점주가 그 숫자로 가격을 정합니다. 그래서 "못 구한 항목"을 항상 함께 표시합니다.

**◈ MVP 화면 및 시연**

| | |
|---|---|
| 서비스 접속 링크 | ⛔ **사장님** — 배포 후 기입 ([배포.md](배포.md)) |
| PIN 안내 | ⛔ 담당자 회신 후 결정 (사장님할것 §2-2) |
| 첨부 화면 | ① 프렙 리드타임 경고 ② 레시피 배수 계산 ③ 오늘 남은 돈 ④ AI 촬영 목록 |

> ### ◤ 자체 채점 — **B (12~13 / 15)**
> **강함**: *"어떤 AI 도구로 어디까지"* 를 묻는 칸에 **Claude Code + Claude API 두 층**을 보여줍니다. 「기술적으로 판단한 것 세 가지」는 *바이브코딩으로 찍어낸 것이 아니라 판단이 들어갔다* 는 증거로 읽힙니다.
> **못 올라가는 이유 두 개**: ① **시연 링크가 아직 없습니다** — 채워지면 **A** 입니다. ② **실사 사진·영상이 0장**이라 첨부 화면이 회색 플레이스홀더입니다.
> ⛔ **테스트 개수를 확정하기 전에는 이 칸을 비워둘 것.** 문서가 537/425 로 갈려 있고 소스 실측은 534입니다. **틀린 숫자를 적으면 20점짜리 신뢰를 15점짜리 칸에서 잃습니다.**

## 4. 지역 연계 및 정착 계획 — **15점**
